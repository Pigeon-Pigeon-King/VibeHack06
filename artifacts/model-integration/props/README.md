# 25 件 Tripo 道具接入记录

状态：25 件道具均已接入真实章节（原 5 件＋本批 20 件），另保留首批 3 件地图类模型。`GeneratedSceneAssets` 继续通过共享 `ModelLibrary` 租约加载，在切关前释放；本轮没有改动其缓存、取消和释放路径。

新增运行文件 **30,977,540 bytes / 29.54 MiB**；25 件道具运行 GLB 共 **38,441,304 bytes / 36.66 MiB**。仅缩减内嵌纹理至最长边 1024，原件与生产记录 SHA 一致且未改写；几何、法线、UV、材质槽及全部非图像 bufferView 不变。没有新生成或付费调用。

[props-to-scenarios.json](props-to-scenarios.json) 记录全部 25 件的逐件章节映射、运行与原始 SHA-256、字节数、位置、尺寸、真实顶点包围盒和支撑说明。[runtime-geometry-audit.json](runtime-geometry-audit.json) 读取了全部 28 个场景模型和 65 个章节放置的真实 GLTF 顶点；无无效顶点或法线。

北闸过滤器／泵组共享一个原子替换槽，在四个实例都加载成功后隐藏旧机组。维修包、工具卷、饭盒与货箱置于原零件架，风机放在原东侧机组平台。运输车和备用门位于既有东侧边界之外，由独立地台承托；备用门没有接管任务门状态。S05、S06、S07 共用这组北闸场景。

S11 的防护／通信小件放在既有工作台或物资箱上，手持终端放在伤情记录台。空转运车停在东侧备用器材位，具有按真实模型包围盒校准的独立碰撞代理；手提担架放在既有物资箱上。三件样本柜替换原东侧储物柜显示，保留原柜保守碰撞包络。全部既有碰撞参数、剧情点及人物路径保持。S12 原接收控制台继续使用生成模型。

验证结果：

- [focused-tests.json](focused-tests.json)：15 项全部通过，覆盖资源校验、25 件映射、真实 GLTF 材质和支撑面、全部医疗目的地／人物路线可达、失败回退、共享租约、取消与重复释放。
- [medical-public-input.json](medical-public-input.json)：既有 S11 公开输入自然流程、允许跳过与逐阶段存档恢复回放通过，三种方式的最终状态相同。
- 初次场景检查在机器争用时有 3 个 5 秒冷启动超时；完整断言重跑全部通过。真实 GLB 数量增加后，将单项几何测试预算调整为 20 秒，没有删除断言。

限制：本批是静态使用／存放接入。装备没有自动穿戴到人物，车辆、担架和门锁没有声称机械分件可动。真实贴图渲染、手机及 Windows 画面仍由主窗口验收；数值几何和自动输入回放不作为真人首通证明。

重新制备可运行 `python3 artifacts/model-integration/props/prepare-props.py SOURCE_CHECKOUT`；该脚本复用既有纹理转换器并复核生产源摘要。逐件转换证据保存在同目录 `PROP-*-textures.json`。
