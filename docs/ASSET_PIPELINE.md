# 原创资产生产与验收接口

本项目采用自制、Tripo／Hyper3D 生成与有来源的可用素材。Blender 用于必要的检查、修整和动画；简单且已符合契约的资产可直接进入 Three.js 验证。当前收到的三个 ZIP 都是资料，29 项资产表是需求清单，尚无对应模型成品随包到达。

基础来源：[当前资产分册](handoff/current/06_ASSETS_HYPER3D_TRIPO.md)、[29 项资产表](handoff/current/data/assets.csv)、[旧 Blender 组织方式](handoff/legacy-himalia/02_BUILD_AND_DELIVERY.md)。旧包的命名、分件与检查方法可参考，地点与范围以当前方案为准。

## 交付链

先查本机已有资产 → 判断直接适配／需要新建 → 资产需求与关卡用途 → ImageGen 概念图（正式新建资产）→ 检查方向、比例、分件和角色身份 → Tripo／Hyper3D 图生模型，或 Dot 云电脑 Blender 建模 → 原始交付 → 修整／绑定／动画 → 运行版 GLB 与附属数据 → Three.js 场景验收 → Windows 包验收。

这是用户选定的项目生产顺序，不表示 Tripo 或 Hyper3D 只支持图生模型。概念图须作为生产输入随资产保存；不让两个服务自行猜测不同的造型。不同角度图需要保持同一身份和结构，多个资产的拼贴不能直接当作一件可分拆模型的合格输入。

Dot 是另一条可用制作路线：向本机 Dot 提供概念图、尺寸、分件、用途与交付要求，由其在云电脑内使用 Blender 建模。用户已提供这条路线；当前尚未提交任务或验证云端连接。输出须带 `.blend` 源文件、运行 GLB、依赖和检查记录，不能只交渲染截图。

已有资产先适配，无需为了遵守概念图流程重新生成相同内容；候选来源见 [本机资产索引](LOCAL_ASSET_SOURCES.md)。首次接入按尺寸、轮廓、许可、动作和渲染成本选取。不得把 1,389 个原始模型与 164 个代码工厂混称为已完成的同等质量转换。

用户明确允许程序化占位符。比例体、方块人物、简单武器和碰撞代理可先用代码建立玩法与接触验证；在清单中标记 placeholder。正式新资产仍走概念图先行流程，替换时保留稳定 ID、挂点和动作接口。

生成成功、文件下载、能导入、动作可用、碰撞可用和实景验收是不同状态。状态建议依次为 planned、briefed、submitted、downloaded、prepared、integrated、validated；不适用的阶段说明原因，不凭预览图直接跳到 validated。

已使用 ImageGen 内置工具完成并检查 [陆闻川成年概念图](../assets/concepts/CH-LU/adult-v2.png)，[提示词与生产状态](../artifacts/asset-jobs/CH-LU-adult-concept.md)已归档。首图方块结构不足，定向修订后选用 v2。本机配置探测显示 Tripo API 密钥未设置，尚未提交任何 3D 生成任务；Hyper3D／Dot 云端连接也未验证。接入服务时重新核对实际插件／API 版本、账户与预算；交接中的 API 迁移日期等外部信息不作为永久有效配置。

## 资产清单字段

建议每件资产在后续运行清单中具有以下字段；它们是本项目约定，尚不是已实现的加载器接口。

| 字段 | 含义与检查 |
| --- | --- |
| id、revision、status | 稳定资产 ID、修订号、真实完成状态；沿用现有 NG／CH／WP 等 ID |
| role、segments | 关卡用途、出现的 S／E 段落与最近观看距离 |
| source | 自制或供应商、来源／许可、任务 ID、参考设计和生成时间；不含 API 密钥 |
| concept | ImageGen 概念图路径、修订号、图像摘要、检查结论、实际提交的图及供应商任务 ID；复用或占位说明豁免原因 |
| original、runtime | 原件与运行版的项目相对位置及校验摘要；不覆盖原件 |
| units、dimensions | 米制、外包围尺寸、角色身高、部件尺寸与允许误差 |
| basis、pivot | 局部上／前轴、原点用途；脚底、门轴、轮轴、枪械握持点分别说明 |
| parts、sockets | 必需分件与命名挂点；可动件的轴与活动范围 |
| materials | 材质、纹理、色彩空间、透明／发光与需烘焙内容 |
| skeleton、clips | 骨架版本、绑定状态、语义动作映射、循环与根运动模式 |
| collision、navigation | 碰撞代理、是否遮挡弹道、是否影响导航、动态状态 |
| lod、budget | 各 LOD 的适用距离、三角形／材质／纹理／骨骼统计；上限按场景测量制定 |
| evidence | 近景、动作、碰撞、关卡和 Windows 验证结果与版本 |

原件、修整源文件和运行资产应分开存放。具体目录随运行工程建立，推荐以 `assets/source/`、`assets/prepared/`、运行资源目录和资产清单区分；生成服务临时下载 URL 不作为运行依赖。

## 模型、材质与空间契约

1. 优先运行格式为 glTF 2.0／GLB；Three.js 使用 GLTFLoader。所有依赖纹理和解码器随运行构建提供。
2. 单位、原点与朝向由资产清单声明。Blender 的 Z-up 到运行 Y-up 转换只做一次；模型正面与相机 −Z 朝向分别校准。
3. 保留原网格、UV、法线、有效材质槽、层级和可动部件。先修理粘连、破面、缺少背面／底部与错误包围盒，不靠暗光隐藏。
4. Blender 中的复杂节点不自动等于运行 PBR；不能直接表达的部分烘焙或重做。检查 base color／emissive 与 normal／roughness／metalness 等贴图的色彩空间和通道。
5. 碰撞代理与渲染模型单独维护。门状态同时更新可见门、遮挡和导航；LOD 必须互斥切换，不能叠在原地重复绘制。
6. 真实交互位置与可达路径由关卡设计确定，不能让一次生成的整体场景锁死拓扑。

官方依据：[glTF 规范](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc)、[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)。

## 武器与手臂

生成枪械基础形态并不自动得到可换弹武器。必须可单独控制弹匣、枪机及需运动的零件，并具有一致的双手接触与瞄具关系。

建议挂点语义：muzzle、gripRight、gripLeft、magazine、sightRear、sightFront、eject。名称可以映射，但含义和局部变换必须稳定。muzzle 的前轴显式记录，不能根据某个模型当前旋转临时猜测。

近景验收覆盖：正常持枪、ADS 瞄具对齐、冲刺退出、射击后坐、完整换弹、切枪、近墙阻挡和不同视野。世界展示用武器可采用较低成本版本，但不能改变主要轮廓与身份。

## 角色与多人动作

2026-10-31 用户补充：角色模型部分产出后，先按 [人物骨骼与动作验收](CHARACTER_RIG_STANDARD.md) 检查，再扩展同批生产。头、胸、腹、左右大小臂／手、左右大小腿／脚必须能分别控制。体型接近的成年人共用一套基础骨架与动作接口，儿童独立适配。概念图审查、网格交付、骨架合格和动作验收分别记录。

成年／儿童、年轻／中年身份分别记录，不将成人骨架简单缩小后视为儿童表演完成。基础角色先检查权重、手指、脚底、转向和所有必要动画片段。

根运动由谁应用必须唯一；AI／玩家控制器与动画不能同时推进相同的位移。动画语义至少区分移动、举枪、射击、装填、受击、倒地与剧情动作。动作按原速起步，再校准步幅与接触。

三条验证线的专用动作：

- V1：父子引导／抱撤、年轻周延受困、班长位置与视线；先用代理检查成年人和儿童接触。
- V2：工人离开作业位、沿后路撤离、队友占位与分批回撤；不以瞬移代替任务到达。
- V3：交出阵位、护具调整、双人搬运孟齐、周延主动求援、担架转运、医护接手与探视。

多人动作采用共享动作锚点、参与者槽位、同步时序和结束站位。每段都测试正常播放、被允许的中断、跳过与检查点恢复。接触、镜头与任务终态一起验收。

原表中父亲、赵启明、孟齐、郑铎、医护与担架等项目虽然为 P1，因用户选择三条线均验证，其必要代理与接口现在纳入早期工作。原表不改写；最终成品优先级按观众实际能看见的内容安排。

环境生成以可复用模块、车辆、机具、道具为单位。不要把整张港口生成成单个不可拆网格；天空、地图方位、任务文字和终端信息由项目统一控制。

当前 `src/presentation/patient-cart.ts` 是床、躺卧患者和附着推车者的程序化接触代理；任务位置来自真实环境碰撞。床体碰撞并不等于完整人体互撞，手握推把、绑带、伤口与医疗操作仍需正式动作验收。

## 单项验收记录

每次入库至少记录：资产 ID／版本、来源、实际文件、尺寸／轴向、材质与纹理依赖、骨骼和动作、碰撞与导航、最近观察截图、相关动作录像、资源成本、通过项与缺口。

在 Blender 看见模型只证明检查环境能打开；Three.js 导入成功只证明格式可读。最终以关卡第一人称画面、任务交互、碰撞／弹道、动画接触及 Windows 包运行共同确认。
