# 重返木卫三项目方案

状态：已完成交接理解与设计归并；本文件描述当前产品要求和拟建架构，具体实现与验证状态见 [持续进度](../artifacts/game-progress.md)。

## 产品与叙事边界

这是约一小时的单人线性双主角 FPS。陆闻川与周延在地球化后的寒冷木卫三港区，推进、守点、护送与接防，为抵近的援军恢复接收条件。核心是复仇机会与对眼前人的责任，以及周延从独自承担转向允许同伴保护自己。

完整结构为序章、占领区、通路、下一班、尾声，共 12 段叙事与 10 组遭遇。首通 55—70 分钟是目标，尚无当前版本实测。每个主关卡都须有真实的进入、推进、交战、穿越和退出区域。

继承的关键因果：

- S08 闻川在完整知情、追击仍可行时兑现护送承诺；不加入假选择或邵原首领战。
- S09 接防人员真实占位，周延交出阵位、接受保护并打算继续生活，成长在此完成。
- S10 已建立的机动力量反扑；协作救回孟齐，周延负伤后主动求援。
- S11 医疗救治失败，周延死亡，孟齐存活；固定剧情结果与普通战斗失败分离。
- S12 闻川接受帮助并继续接收；邵原逃离，赢得的是援军进场机会。

依据：[产品方向](handoff/current/01_PRODUCT_VISION.md)、[人物与成长](handoff/current/03_CHARACTERS_AND_ARCS.md)、[十二段制作卡](handoff/current/04_CAMPAIGN_AND_LEVELS.md)。不增加多人、开放世界、技能树、载具驾驶或分支结局。

## 本轮用户选择与推进方式

用户要求时间紧的情况下，尽可能把此前提出的三个范围都进行验证；开发顺利时继续完成剩余内容。由此采用三条验证线共享基础系统的方式，完整战役范围保持不变。

后续补充：架构台完成后直接逐模块制作，已建立长期目标持续推进。首轮允许程序化占位符；美术方向为方块人物配更精细、形体自由的工业场景，见 [美术方向](../design/ART_DIRECTION.md)。正式新资产按 ImageGen 概念图 → 图生模型或 Dot 云电脑 Blender 的流程生产；先检索 [本机军事库](LOCAL_ASSET_SOURCES.md) 中适用的既有内容。

这里的 S08—S11 是跨越多处场地的关键叙事链，不把它压成一个房间；先验证最难的转接和接触动作，再连接完整护送与战斗过程。

| 验证线 | 内容 | 必须证明的结果 |
| --- | --- | --- |
| V1 序章 | S01 检修门＋S02 主厅／E00；儿童与年轻周延两个视点 | 两个视点共享一致空间；父子接触、撤离、坍塌和控制权交接可读；救出的人有效撤走，剧情失守不冒充失败 |
| V2 北闸 | S05／E04，北路初接敌→称重台→东侧压力→分批撤回 | 真实弹丸、掩体、敌人展开、工人实际到达、队友接替、撤离收束和重试形成完整循环 |
| V3 关系与救援 | S08 取舍→S09 换班→S10 协作救援→S11 医疗 | 信息齐备、人员交接有效、先成长后负伤、多人接触成立、跳过与正常演出的任务终态一致 |

V2 适合最早检验系统联动，V1 与 V3 的高风险接触动作可以在共享代理场景中同期准备。这里的“同期”是工作依赖设计，不表示已经启动多个代理。资产按三条线共同需要的角色、手臂、门、担架和港区模块优先安排。

## 运行架构建议

建议以 TypeScript＋Vite 组织 Three.js 游戏；先以 WebGL2 为兼容基线，Electron 作为 Windows 桌面封装候选。版本在创建运行工程时固定并写锁文件；此处不把旧示例的依赖版本直接作为项目版本。

下列是职责边界。首轮代码已建立 `src/runtime`、`src/player`、`src/combat`、`src/actors`、`src/mission`、`src/presentation`、`src/content`、`src/ui` 和 `desktop`；协作演出当前由 Simulation 统一状态，后续内容扩展时再拆分。实现与实际验证范围见持续进度，不把目录存在视为完整模块验收。

| 模块 ID | 拟建职责 | 关键接口与约束 |
| --- | --- | --- |
| runtime | 启动、资源加载、主循环、暂停、切场景 | 唯一仿真时钟；加载失败可见；释放旧场景 |
| player | 输入、步行／冲刺／蹲跳、ADS、交互 | InputState → PlayerController；相机表现不反写物理位置 |
| ballistics | 武器状态、弹丸积分、碰撞扫掠、伤害 | WeaponState → Projectile → HitEvent；飞行时间和当地重力统一 |
| actors | NPC 身份、导航、感知、战斗、动画与死亡 | 行为、物理位置和表现分层；任务人物由稳定 ID 识别 |
| mission | 目标事实、遭遇阶段、检查点与角色知识 | 人员到达／设备状态等事实推动进度；不可用计时器假完成 |
| staging | 作战、工作、协作、固定演出控制权 | 每段声明进入条件、占用资源、跳过终态、恢复输入 |
| presentation | 世界、木星天空、灯光、音频、HUD 与字幕 | 世界方向统一；第一人称可读；多站位验证动作与视线 |
| assets | 生产记录、导入、角色／武器／场景契约 | 来源、原件、运行版和验收分别记录；无浏览器凭据 |
| desktop | Windows 容器、构建、存档适配、退出／恢复 | 只暴露必要平台接口；从安装包实际运行验收 |

建议目录：`src/runtime/`、`src/player/`、`src/combat/`、`src/actors/`、`src/mission/`、`src/staging/`、`src/presentation/`、`src/content/`、`desktop/`。共享类型放在明确的契约模块，避免循环依赖和各系统自行复制状态。

## 共享状态与数据流

### 玩家与战斗

输入记录意图，玩家控制器通过碰撞系统更新身体位置，再生成相机的基础姿态。后坐力、呼吸、受击和摇晃是表现偏移，不能逐帧累积污染身体位置。武器状态机决定何时能发射和何时补弹，弹丸系统独立处理飞行、扫掠与伤害。

射线查询可以用于准星选点、弹丸一小步的扫掠和可见性；本项目枪械不在按下开火的那一帧直接对全射程目标结算伤害。尸体与弹壳使用同一世界重力，人员的接地控制单独建模。

### 任务与检查点

事件至少包括人员进入安全区、门状态变化、通信接通、阵位交接、伤员转移和攻击造成的伤害。MissionState 读取这些事实，驱动遭遇阶段、字幕信息与检查点。敌人数是压力预算，不是每阶段必须杀完的配额。

检查点保存角色 ID／视点、人物状态、门与设备、弹药、目标事实、遭遇阶段、角色已知信息以及演出终态。复位时清除旧弹丸、监听、音频和临时特效；恢复时不重复执行一次性事件。剧情固定伤情与普通生命值分开存储。

### 演出与人物

控制权统一为 combat、work、cooperative、staged 四种模式。系统显式声明可移动、可观察、可开火、可交互与可跳过的能力，避免分别改动若干互相矛盾的布尔值。演出进入需验证站位与路径，跳过需应用同一个终态，不跳过未完成战斗。

V1 的父子抱撤、V3 的护具调整／双人搬运／担架交接，在成品模型到齐前先用比例正确的代理体验证。代理体通过只证明动作接口，不代表美术完成。

## 世界与关卡组织

运行时建议统一米制、+Y 向上、−Z 为地理北、+X 为东；模型局部正面单独记在资产清单。旧地图高程为 Z 的数据须转换，不能直接套用。

木星固定在世界天空方向，采用交接给出的约方位 93°、仰角 16°、视直径 7.7°作为制作工作值；这些不是本次天文模拟结果。天空可随相机平移居中，但不能继承相机视角旋转使木星粘在屏幕上。

关卡按实际职责拆分可加载区域，远景与可玩区分开。每区具有渲染几何、简化碰撞、导航数据、出生入口、NPC 等待／作业位、任务触发区和演出锚点。动态门、可移动掩体与静态结构分别处理；导航与弹道遮挡跟随状态。

来源：[世界设定](handoff/current/02_WORLD_AND_STORY.md)、[战役与地图连接](handoff/current/04_CAMPAIGN_AND_LEVELS.md)。

## 资产优先级对本轮选择的调整

原交接表的 29 项需求保留原样。本轮增加三条验证线后，父亲／儿童代理、赵启明代理、门口／坍塌遮挡、孟齐／郑铎代理、护具、担架和医护站位都属于早期验证所需。其代理制作与接口验证优先级上调，不代表所有角色最终高精模型必须先于射击基础完成。

高精成品按最近观看距离与叙事重要性逐批替换；三条线至少各有一段代表性第一人称美术、动画、音效和字幕共同验收。详见 [资产接口](ASSET_PIPELINE.md)。

## 设计参数与完成证据

当前继承成人移速 2.1／6.3／1.35 m/s、世界重力约 1.428 m/s²。跳跃初速 1.65 m/s、每场同时 8—12 名活动敌人、1080p／60fps 及全片 256—348 入场敌人均是验证起点或候选预算。

本轮没有确定 Windows 硬件、付费生成额度、最终枪型、最终外貌声线或固定模型面数。已有材料足以安排工程，具体数值在相关步骤通过实际证据定型。

开发完成需要同时看到：实际输入、画面、任务状态、角色行为、失败与重试、声音和目标平台表现。旧北闸测试、文档中的流程图和自动演出均不能替代本项目这些证据。
