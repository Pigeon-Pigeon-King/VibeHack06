## 交给主窗口的顺序

1. 将美术、声音、反馈和手机模块整合到一份可回溯的运行版本；声明仍保留的占位资产和未验事项。
2. 冻结代码与运行资源，记录 commit、锁文件及实际文件散列。在隔离输出中构建，复查对应网页和 Windows 包。不要覆盖其他窗口正在使用的 `dist` 或 `release`。
3. 从同一构建拍摄宣传片与正常速度玩法备用录像，保存原始带 HUD 镜头、录制方法及检查点来源。填完本地备演设备记录后排练 180 秒展示。
4. 根据这份实际构建更新表单文案，补入真实的队伍、工具、网站和源码链接。公开访问、私库协作者和比赛提交只按用户后续明确授权执行；当前指令仍是先完成游戏、暂不发布。
5. 以后获准发布时，从外部设备实测最终链接并保存官网回执；本地 URL、保存草稿、包已生成都不能代替这一步。

本窗口没有修改原剧情、运行代码、共享资产、已有 Git 历史或公共进度。已批准 GLB/声音继续遵循本项目资产流程；托管路线不会自动取消这些批准。
