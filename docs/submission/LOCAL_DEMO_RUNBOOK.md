## 四种材料要当场说清

| 类型 | 能证明的范围 | 必须使用的说法 |
| --- | --- | --- |
| 现场输入 | 观众面前键鼠输入及实际响应 | “现场操作”；若从导入检查点开始，加“局部恢复” |
| 本地实机录像 | 已录制构建中的可见玩法；不是现在输入 | “同版本地实机录像”，记录正常速度、实际录制者与源文件 |

本卡主方案是 A：S10 开发章节入口现场 Q，B：从既有检查点恢复后现场搬运。它不是一次无切换的 S10 首通。游戏内诊断中的玩家“命中”数只记玩家弹丸；不能用它认定郑铎命中。同伴伤害来自独立弹丸分支，现场要拍清枪口、弹道／敌人反应；诊断事实只作补充证据。

## 启动方式与端口隔离

已核实 package.json 的 dev、preview、build 与 desktop 脚本，vite.config.ts 的相对 base 为 ./。选择**自己的**终端与浏览器窗口，不关闭、重用或抢占别人端口／标签页。

| 用途 | 实际支持的命令 | 入口与边界 |
| --- | --- | --- |
| 本地开发备演（主方案） | npm run dev -- --port 5193 | http://127.0.0.1:5193/。Vite dev；支持开发章节与检查点导入。已有 strictPort，端口占用就停止，不杀占用进程。5193 是拟用空闲端口，本文未探测／启动它。 |
| 生产网页离线备用 | 事先 npm run build，然后 npm run preview -- --port 5194 | http://127.0.0.1:5194/。读取 dist；没有 DEV 检查点导入，也没有 S01—S12 独立开发章节菜单。应提前用此 origin 正常游玩形成连续战役存档，或只用公开入口展示。本文未构建／启动。 |
| Mac 本机桌面候选 | 事先 npm run build，然后 npm run desktop | Electron 读取生产 dist。同样不包含 DEV 导入入口；与浏览器不共用存档。本卡未运行。 |
| Windows 便携备用 | 在 Windows 上完整解压经核验的对应版本目录，再启动其 ReturnToGanymede.exe | 项目已有历史候选包，不能称其含最新资产／字幕／反馈。只有最终包在 Windows 真机验证后才可用作可靠现场备用；当前 NOT_RUN。 |

依赖须事先安装齐全；联网准备时才执行 npm ci。备演当天不要把 npm ci、生产构建或资产下载计入 180 秒。上台前确认 Node／npm 可用、node_modules 与实际构建文件存在；断网后打开并操作所需场景，验证全部资源来自本地。这里只给出已存在的启动脚本，不承诺尚未实测的断网运行。

本轮 shell 的 PATH 没有 Node，已采用仓库既有路径运行唯一一次几何检查，未安装新环境。若备演终端相同，先在自己的终端启用现有运行时（node 与 npm 文件均已确认存在），再执行上表命令：

~~~sh
export PATH="/Users/penguin/.local/node-runtime/node-v22.14.0-darwin-arm64/bin:$PATH"
node --version
npm --version
~~~

这是本机准备路径，不得写进网页运行资源依赖或对外玩家说明。实际安装位置变化时重新核对，不修改 HOME／CODEX_HOME，也不清理别人的依赖目录。

生产 dist 不能用 file:// 双击代替 HTTP 服务；ES modules、资源加载与浏览器来源语义不同。默认 5188 是主线开发端口，5191 是其它窗口的本地候选；二者都不是公网链接。5193／5194 不与这些端口共享本机存档；端口、浏览器配置、Electron 用户目录改变都需要重新备演。不要通过修改 localStorage 或控制台写状态来临时“跳到”演示位置。

## 场前准备 A：Q 掩护（真实已有入口）

1. 用专门的备演浏览器配置／窗口打开自己启动的 5193。避免清理或覆盖用户现有存档。
2. 主菜单展开“独立验证场景”，点 **S10 · 共同撤回**。这是 GameUI.ts 与 CHAPTER_STAGES 在 import.meta.env.DEV 下生成的真实按钮；不输入未实现的 URL 跳关参数。
3. 独立入口会恢复该槽未完成的检查点。若不是开场“压住设备廊交叉口”，按 Esc → “重开本场”，重置的是此独立 S10 槽。不能按“从序章重新开始”来准备局部演示。
4. 从出生位置附近走到腰高遮护后。源码回归中的观察参考是玩家约 [-6, 0, 189]，相邻掩体约 [-4, 0, 190]；坐标只供场前在开发诊断里定位，不需要念给观众。按住 C 可蹲伏。
5. **先不要按 Q 或开火。** 记住郑铎原站位和玩家弹药，Esc 暂停；这是 A 的起播状态。场前截图应记录真正画面和基线。
6. 路演 01:05 切回 A，点“继续行动”。01:12 按一次 Q 后松开，玩家继续留在掩体，不按左键／F。Q 是按下事件，不用反复连按。
7. 观察郑铎走向侧位，实际开火与敌方反应；玩家弹药应保持不变。源码仅在 phase 0／2、郑铎尚未开始接伤员且该阶段未请求过时接受 Q。同一阶段连按不会反复下令。
8. 到 01:40 无论结果怎样都松开输入并 Esc 暂停，照稿说明切检查点。不能为了“准点命中”修改伤害、删除敌人或快放仿真。

实际代码：Rescue.ts 的 Q 分支给郑铎路径；Simulation.ts 同伴开火由 Ballistics 发出，碰撞敌方后扣生命并短暂打断瞄准。既有 finale-interactions 回归在玩家完全不射击时记录了郑铎位移、自身弹丸与敌人掉血；历史浏览器观察未拍到枪口瞬间。因此**当前代码支持 ≠ 本次现场镜头已经可读**，28 秒窗口需真人排练。

## 场前准备 B：既有搬运检查点

1. 在自己的第二个标签 B 打开同一开发入口，主菜单 → “独立验证场景” → **“检查点文件（开发验收）”**。
2. 选择项目内已有文件 tests/fixtures/finale/rescue-4.json，不编辑内容。来源文件为同目录 rescue-4.source.json：kind=public-intent-replay-checkpoint，sourceTest=tests/finale-paths.test.ts，phase=4，phaseTime=0。它来自自动公开输入回放，绝不是真人全程录像。
3. 文件 SHA-256 应为 d7a89cd64aa483b07cf4acb24bf51740edcd43a1a248acf35b2a063b25a26b19。导入沿 SaveStore 严格解析，隔离内存且禁止写入玩家常规存档。若冻结版本不兼容，应重新通过真实公开输入获取有来源的检查点；不能删校验字段硬塞。
4. 载入后应显示“S10 · 共同撤回”及“共同抬到西侧硬遮护”，并有“检查点恢复 · 局部视觉验收”诊断标记。初始玩家约 [-29.93, 0.015, 225.93]，孟齐已由两人接住。当前文件弹药为 9／150；冻结版本以实际读数为准，拍前记下。
5. 立即 Esc 暂停，切回 A。切标签会触发失焦暂停；路演 01:40—01:50 用真实用户点击恢复 B。不假定切回来会自动战斗。
6. 01:50 点“继续行动”，用鼠标朝西侧目标调整视线，再用 WASD 慢行。协作速度由代码限制为 1.5 m/s，Shift 不会把它变成奔跑；占用双手不能射击／换弹。短按 F 后松开，观察弹药与发射数不增加。
7. 到达遮护的条件不是玩家单独踩点：玩家距 carryEnd 小于0.3米，孟齐与郑铎也须分别到位。目标应变为“同伴已进遮护，继续撤入缺口”。立即 Esc 暂停，把结果留给 02:30—02:40 讲解。
8. phase 5 以后是固定负伤和求援链；不要用 Enter 跳到“送抵”当作搬运证据，也不要误称剧情负伤是现场操作失败。

可靠直线路线：从当前检查点沿西向“转运接力位”移动至遮护，保持队形。床体比玩家胶囊宽，视角能过不代表担架能过。方向键可转向、F 可开火，均是 Input.ts 已有替代输入；没有额外跳关快捷键。

## 可选原生挡墙路线：先排练，再进入 15 秒受阻段

已有机制测试使用过测试专用障碍；**那个注入障碍不是现场场景功能**，不能写作玩家可打开的“阻挡演示开关”。本卡另提供只用真实 rescue-hard-cover 的观察路线：

- 在 phase 4 先向西走到约 x=-39、z=225.93，再轻微靠北至 z≈225.35；继续向西，床体接近原生挡墙南缘。窄余量用于让床体受阻而玩家仍有退路。
- 当队形受牵制而前进停止，保持不超过 2 秒给观众看清；然后朝东退约 1.5 秒，向南让到 z≈226.05，再向西跟目标走到遮护。
- 使用自然键鼠输入；这里的坐标是场前理解路线的参考，不能在演示时调用 teleport、改玩家位置、增加碰撞盒或写任务事实。
- [轻量几何侦察脚本](../../artifacts/trailer-45s/rehearsal-geometry.check.ts) 已单独运行一次、1项通过；[结果](../../artifacts/trailer-45s/rehearsal-geometry.json)记录原生挡墙处继续前推2秒水平位移为0、退让约2.10米、随后到达遮护，玩家没有耗弹或发射。只使用现成检查点、公开 Intent 和现有世界碰撞，没有注入障碍或修改任务事实。这只证明数值路线，不证明人能在15秒内精准操控、画面可读或当前设备帧率；真人路线和计时仍为NOT_RUN。
- 这条路线对贴墙位置很敏感。若真人排练不能稳定复现，主路演改用直线搬运和稿内如实替换句；不要临场反复挤墙拖过 02:15 的时标。

## E 起手的单独补验（不硬塞进 95 秒）

B 的 phase 4 已经完成接手，不能拿它证明本次按 E 起抬。若需要展示 E，场前另从 S10 入口正常推进到孟齐负伤后的 phase 2：控制近处火线，等郑铎真实走到另一侧，靠近担架左端，出现“E 协助转移孟齐”才按一次 E。接手演出约六秒，随后才进入搬运。

本轮没有提供或虚造 phase 2 导入文件。该步骤可用于后续人工备用录像；当前完整真人路线及耗时 NOT_RUN。路演讲解中的“共同抬着”准确描述 B 起点，不说观众已看过接手全过程。

## 故障切换与本地备份

| 触发 | 立即动作 | 现场说明与边界 |
| --- | --- | --- |
| 鼠标锁定失败 | 点击画面重试一次；仍失败，用方向键观察、WASD／Q／F；最多占当前段 5 秒 | “切到键盘替代输入。” 不打开控制台或触碰其它窗口。 |
| Q 无响应 | 核对是 phase 0／2、有无本阶段请求、是否失焦暂停；场前重开准备，台上不长时间排查 | 没看到命中就用路演替换句；字幕回应不等于命中。 |
| 普通战斗倒下 | “重试检查点”；若当前段剩余时间不足，切已核验的同版实机备份 | 明说“现在是本地录像”。旧测试画面不能替代最终整合版。 |
| 搬运卡住 | 松开输入，朝原来把手方向退让；仍未恢复就 Esc 暂停，按未完成结果口述 | 不强行穿墙，不把未到位说成完成。 |
| 场景导入失败 | 停用 B 导入分支；只用已验证的兼容检查点或同版人工录像 | production dist 没有开发导入入口，不能临时许诺可以导入。 |
| 声音未解锁／音频失败 | 以真实点击恢复一次；仍失败保留字幕与真实视觉反馈 | 不播放与当前动作不同步的枪声／命中音制造效果。 |
| 网络断开 | 本地服务器和全部已安装资源继续按事先断网验收结果使用 | 断网首开未试过就不能宣称离线可靠。 |
| 开发服务退出／WebGL context lost | 不在台上重装依赖；一次刷新／恢复，失败即切合规本地录像 | 当前没有已验备用视频则如实报告故障，03:00 仍结束。 |
| 45 秒片播放失败 | 切事先完整观看过的相同文件第二份本地副本；仍失败则取消播片并直接进入玩法 | 未播放的宣传片不计完成；压缩口述、保留操作。180 秒是上限，故障时可提前结束，不用占位视频填满。 |
| 需要临时换生产网页／EXE | 只切已验证并已备好真实连续存档的实例 | 无开发导入；没有预备存档就从公开入口演示并改口径，不能谎称已恢复 S10。 |

建议在冻结版本后建立本地材料目录，登记 45 秒带字幕片、无字幕母版、两段正常速度人工玩法备份、原片／构建摘要与本操作卡。当前这些视频均未制作；capture-manifest.template.json 保留空值表示“未录”，不能把模板当证据。

不要录制尚未整合的候选冒充最终素材。不需要互联网的本地服务也不是公网试玩。手机真机输入、多指、性能与 Windows EXE 实机仍分别验收。
