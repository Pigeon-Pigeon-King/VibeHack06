## 本项目交付组合

保留完整战役产品，同时建立比赛演示入口与冻结的参赛版本。以下为项目准备项，不全部冒充官方必交附件：

1. **在线试玩**：从同一源码构建，具有目标、操作、挑战、成功／失败及重试；现场可快速进入已经验证的玩法段落，正常战役入口仍保留。演示入口尚待设计与实测，不能把开发存档导入工具直接当作发布功能。
2. **GitHub 源码与过程**：保存真实开发历史、启动方式、工具／模型用途、已实现内容与限制。公开可见作品页不等于必须把源码设为公开。私有邀请属于需明确授权的访问变更。
3. **Windows 便携版**：作为用户要求的 EXE 目标及现场断网备用，保留完整解压目录、启动说明和许可证。当前有基线 ZIP，但未在 Windows 实机验证，且该 ZIP 不包含后续 HUD 提交；不得把它标为最新最终版。
4. **宣传片与玩法备用录像**：45 秒实机宣传片沿用 [分镜](../design/TRAILER_45S.md)；另留一段能看清核心操作与结果的正常速度录屏，应对网络或设备问题。录屏、现场操作、概念设计明确区分。
5. **截图、简介、来源记录**：与最终提交构建一致；记录参赛提交 commit、构建时间、包摘要、URL 和已知限制，避免官网、视频与下载版指向不同状态。

> 《重返木卫三》是一款原创科幻第一人称射击战役。玩家以陆闻川与周延两个视点，在木卫三工业港区交战、掩护撤离并协作转运伤员，为援军恢复接收条件。核心目标是把眼前的人交给下一班：同伴掩护能实际命中与压制敌人，协作搬运受到队形和环境碰撞约束，居民根据安全与到达条件自主行动。
>
> 当前为开发中的可玩 Demo，S01—S12 功能白盒已连通；正式模型、完整配音、连续演出和全战役时长仍在制作与验收。完整产品目标约一小时，不以现有自动回放或局部演示声称已达成。
>
> WASD 移动，Shift 冲刺，C 蹲伏，Space 跳跃，鼠标观察，左键射击，右键瞄准，R 换弹，E 亲手交互，Q 在适用场景请求掩护，Esc 暂停与重试。请使用桌面电脑和键盘鼠标。

## 三分钟路演建议

| 时间 | 展示内容 | 要证明的事情 |
| --- | --- | --- |
| 0:00—0:20 | 一句话介绍角色、场景与任务 | 观众知道玩家是谁、要完成什么 |
| 0:20—1:05 | 45 秒宣传片 | 原创角色、气氛和故事钩子；素材要与实际状态一致 |
| 1:05—2:40 | 95 秒真实玩法，重点同伴掩护与协作转运 | Q 后同伴确有行动与射击结果，玩家承担操作、承担风险，目标有清楚反馈 |
| 2:40—3:00 | 简述 Vibe Coding 制作方式、当前完成项，展示试玩入口 | 作品能继续被评委实际试玩 |

具体玩法段落需先排练计时；若 95 秒不足以读懂交互，调整宣传片或口述时间，优先保留可读的操作与反馈。不通过加速画面、跳状态或剪辑拼接伪装连续现场操作。指南只要求三分钟及清楚演示，以上分配为本项目建议。

## 截止前执行顺序

1. 核对用户已有队伍、报名账号及 Build in Public 链接；准备 GitHub 远程方式和部署目的地，避免重复创建已有成果。
2. 继续完成玩法与资产制作，在提交前冻结一个实际可演示的 commit；若并行窗口仍在工作，逐项说明哪些改动已纳入。
3. 构建网页与 Windows 候选，补齐网页第三方许可；在所选演示设备上检查鼠标锁定、射击／协作、失败与重试、声音、刷新恢复，以及资源加载。
4. 部署后用未依赖开发环境的入口检查网站；核对 GitHub 对评委可访问、图片与视频可播放、Windows ZIP 可完整解压。Windows 启动验收需在 Windows 完成，Mac 打包检查不能代替。
5. 由一位成员填写／更新同一份提交表单，核实所有工具和模型为真实使用；**建议 17:30 前完成提交，预留 30 分钟处理问题**。17:30 是项目缓冲建议，官方截止仍为 18:00。
6. 回到官网活动页核对公开项目，记录提交成功证据和最终链接；下载本地包与视频作为现场备用。不能因保存了草稿而认定已提交成功。
