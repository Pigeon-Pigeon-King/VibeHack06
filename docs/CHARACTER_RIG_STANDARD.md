# 人物骨骼与动作验收

依据：用户 2026-10-31 补充。此文件是正式角色的生产和验收约定；当前程序化白盒与人物概念图均不能证明模型已绑定。资产总流程见 [ASSET_PIPELINE](ASSET_PIPELINE.md)。

现有检查工具：`npm run audit:rig -- --file <本地GLB> --map <语义映射JSON> --out <报告JSON>`。真实主角首批绑定模型、逐关节映射及成人共用检查见 [运行资产接入](IMPORTED_ASSET_RUNTIME.md) 和 `artifacts/rig-audit-20261031/`。CLI 会检查实际蒙皮与辅助骨架，不解码图片；结构通过不能替代逐关节观看、共享动作和接触验收。

## 统一成人基础骨架

身高、体型接近的成年人使用版本化的同一骨架层级、关节语义、参考姿势与动画接口，保留各自网格、服装和材质。年轻／中年身份不必各建一套骨架。先选一名成人完成标准骨架，再把第二名成人绑定到相同规范，实际验证动作共用，之后扩展其他成人。

最少区分下列控制部位；左右不能混用，头、胸、腹不能合为一个不可动部件。骨骼命名可以由导入映射统一，但交付清单必须逐项对应：

```text
root                    全角色运动根
└─ pelvis               骨盆
   ├─ abdomen           腹／腰
   │  └─ chest          胸
   │     ├─ neck → head 颈与头
   │     ├─ clavicle.L → upper_arm.L → forearm.L → hand.L
   │     └─ clavicle.R → upper_arm.R → forearm.R → hand.R
   ├─ thigh.L → shin.L → foot.L → toe.L
   └─ thigh.R → shin.R → foot.R → toe.R
```

颈、锁骨和脚尖用于转头、抬臂及步态接触，随基础骨架统一保留。手掌必须可独立摆动；近景持枪、抬担架需要稳定的握持姿态，手指是否逐节控制按最终方块造型与动作需要裁决。武器握持、枪口、背负物及搬运接触点由统一挂点接口给出。

方块造型采用可弯折的分段结构：肩、肘、腕、髋、膝、踝的旋转中心应处于实际关节；护膝、袖口与厚衣摆留出活动间隙。可使用分件刚性权重或经过控制的过渡权重，转动时不得把胸腹拉成胶皮、把肢体扭细或让关节无故断开。网格分件、骨骼层级与碰撞体是分别检查的内容。

## 儿童与体型差异

儿童单独制作比例正确的骨架与参考姿势；头身比、躯干、四肢长度和关节位置均应与审定设计一致。可共享语义命名和动作状态机，动作须重新校准步幅、重心、抱持位置和手脚接触。成年人的动作缩放不算儿童动作验收。

成年人共享骨架时，逐人记录身高、肩宽、臂展和腿长。存在明显比例差异时保留同一语义接口，允许重定向和角色校正；不要为了套骨架改变已审定的角色身份。父子抱撤必须同时检查成人和儿童骨架、抱持锚点与结束站位。

## 首批模型产出后的检查

1. 先检查一个成人代表及其运行版 GLB：单位与轴向、根节点、骨架层级、休止姿势、左右标记、逆绑定矩阵、缩放、网格依赖和材质完整性。原始模型、修整源文件及运行文件分别保存。
2. 逐个旋转上述部位，覆盖颈、腰、肩、肘、腕、髋、膝、踝。记录穿插、粘连、拉伸、权重串动、根漂移和关节空隙；不能只展示站姿判断合格。
3. 验证第二名成人是否真正共用骨架与动作，检查持枪双手、脚底及装备用点。确认后再把同一方案推广到其他成人。
4. 单独检查儿童代表。父亲抱撤、儿童转头／步行必须在两个人的实际骨架上验证。
5. 在 Three.js 实机测试待机、走、跑、转向、瞄准、射击、装填、蹲、跪、坐、受击、倒地／躺卧，以及抬伤员、推患者车、扶门、照护等相应角色动作。记录关节近景和整段动作录像。
6. 对多人动作检查手与抓握点、脚与地面、躯干与担架接触；启动、循环、结束及允许的中断／跳过／检查点恢复均保持稳定。位移由游戏控制器或动画其中一方统一负责。

这些动画部位不自动定义伤害倍率；命中区与伤害规则属于玩法裁决，另行保持一致。

## 验收记录

每件角色记录 `assetId`、概念图版本、原始／修整／GLB 路径与摘要、`rigVersion`、骨骼语义映射、身高及参考姿势、权重方式、共用动作与校正、逐关节检查结果、多人动作接触、Three.js 录像及未解决问题。骨架阶段区分“待建模”“网格已检查”“骨架已检查”“蒙皮已检查”“动作已检查”“实机已检查”。缺少实际模型时保持待检查。

所有角色概念图仍先交用户整体审查；首批生产及骨架验证不代替概念方向批准。美术生产窗口负责模型与动作交付，问题反馈窗口可接收穿模／关节／动作故障并跟踪修复，玩法窗口负责动作用途和协作规则。
