## 分册：01_PRODUCT_VISION.md

# 01 · 产品方向

## 一句话
在地球化后的木卫三，一名追查杀父仇人的年轻维修工和一名背负幸存负担的老兵，必须在援军抵近之际夺回港口接收能力。玩家通过推进、守点、护送和换班，经历他们怎样把个人复仇放到共同光复之中。

## 玩家最后应记住什么
天空中木星一直在原处；有人已经见不到恢复工作的港口。玩家亲手保护过的工人、车辆、伤员和通信，最后让第一批运输舰得以进场。故乡的回归体现在这些具体结果里。

陆闻川没有放下全部仇恨。他知道追击机会确实存在，也知道抽走护送和换班力量会让谁承担代价。周延没有用死证明忠诚：他先学会交出位置、接受保护并打算活下去，之后才在共同撤回中受伤。

## 已确认的产品边界
| 维度 | 当前方向 |
| --- | --- |
| 类型 | 单人、线性、固定主线、双主角第一人称 FPS |
| 篇幅 | 完整作品约 60 分钟；普通难度首次正常通关 55—70 分钟是待验证目标 |
| 结构 | 序章＋三个主战役关卡＋尾声；12 个叙事段落，10 组战斗遭遇 |
| 情绪 | 严肃战争、占领生活、具体的人际责任；悲剧结尾中保留真实成果 |
| 世界 | 木卫三，远未来地球化后的寒冷工业港，有大气、云、风、冰脊和露天街区 |
| 技术终端 | Three.js；桌面键鼠优先，预留手柄与可调字幕；开发转到 Mac |
| 美术 | 写实人体比例、可信工程与生活痕迹、克制军事科幻；COD Modern Warfare 是阅读与操作体验参照 |
| 演出 | 过场与即时演算合为同一套引擎内演出；逐段规定控制权 |
| 资产 | 自制＋Hyper3D / Tripo＋现有可复用素材；可以重新制作具体地图 |
| 语言 | 中文对白与底部说话者字幕 |
| 结局 | 周延死亡，陆闻川、孟齐存活，邵原逃离；只争取到援军进场机会 |

不扩展多人、开放世界、基地建设、技能树、制作树、载具驾驶、太空战、低重力跳跃解谜或分支结局。移动有跳跃功能，但地图不依赖高难跳台。主线没有饥饿、体温、氧气或辐射数值管理。

## 五项体验要求
**战斗要有行动目标。** 枪战为开通道路、保护作业、护送和接防服务。敌人倒下、同伴占位、居民通过和设备恢复共同推动阶段，不能靠播放时间结束战斗。

**世界先有用途。** 北闸原本是称重、安检、维修和通勤场地。车辆、货架、维修机组、征用物资自然成为掩体；每块遮护都能解释为何在这里。

**地图容得下真实的人。** 首次玩家会看错方向、空枪换弹、冲过掩体、后退和漏听报点。路线要给观察、交火、恢复和再推进留空间，群众与战斗人物不能挤在同一条轨迹上。

**成长要变成行为。** 周延共享信息、采用孟齐方案、让别人接替；闻川兑现护送承诺、承认不公指责、最后如实汇报并接受帮助。玩家看见这些决定的结果。

**画面与声音共同成立。** 同一片段要同时有合适模型、比例、材质、灯光、动画、枪声与操作反馈。只有一张好看的鸟瞰图、箭头路线或自动演出视频都不足以证明完成。

## 保留什么，重新做什么
保留：人物关系、信息顺序、主要事件、地图的地理职责、天空一致性、操作需求、试玩发现和可用资产。

可以重新做：房间布局、路线细节、敌人部署、地图长度、技术架构、具体枪型、灯光方案、所有不达标的模型与动画。现有原型是参考，不是必须迁移的技术底座。

完整战役始终是产品目标。比赛若先做片段，必须明确叫“战役切片”，并保留后续三关结构；本次没有把用户的目标改成几分钟小样。

## 衡量是否接近目标
真人能说清当前是谁、要保护谁、敌人从哪里来，能犯错后恢复，能理解复仇机会的代价，也能复述周延“先接受换班，后负伤”的顺序。全程计时按互斥活动记录，画质与性能在实际 Mac 和浏览器测量。当前没有全战役真人通过率、平均首通时长或统一 60 fps 的证明。

依据：原作事实表、当前产品简报、战役规模修订、GAME_DESIGN 最新修订及用户多轮试玩反馈，见 [来源索引](SOURCE_INDEX.md)。

# 02 · 世界与故事

## 从木卫六迁到木卫三
原小说《重返木卫六》完整保留为文学来源。后来用户希望第一人称室外能看见明显的木星，并明确选择木卫三、增强磁防护和可呼吸大气。当前工作标题为《重返木卫三》。接手者应在需要改写正文时逐段迁移天文与环境描写，保留人物因果；不能仅凭旧文件夹名把场景做回木卫六。

## 世界规则
| 项目 | 当前设定与制作后果 | 属性 |
| --- | --- | --- |
| 地表 | 古老暗色冰质地形、浅色沟槽冰脊、填筑作业坪、隔热基础；远郊是寒冷冰原 | 现实地貌启发＋虚构城市 |
| 磁防护 | 天然磁场增强、粒子环境管理、厚大气和建筑共同提供露天活动条件 | 明确的远未来假设；不是可见能量罩 |
| 空气 | 跨世代输入挥发物和制气，全球可呼吸大气，港区约 90 kPa 为工作设定 | 虚构；不把磁场当作空气来源 |
| 温度 | 本次室外约 -8°C，室内约 16—20°C；人工能源与长期气候管理支撑 | 创作参数，未完成全球气候模拟 |
| 重力 | 约 1.428 m/s²；地球化不改变天体重力；牵引鞋和助力护具帮助接地与制动 | 自然重力＋科幻装备 |
| 室外服装 | 保暖工服、手套、护目、护甲，常规场地能露面和呼吸 | 用户确认方向 |
| 门的功能 | 防风、保温、消防、隔离；旧气闸可改作门厅 | 正常通行不反复升压 |
| 日常 | 维修、学校通勤、热水、医疗、温室与公共标识，几代居民在此出生 | 世界塑造 |
| 太阳 | 远处太阳仍可照亮地面；供暖不靠日照单独完成 | 参考现有科幻设定稿 |
| 大气危险 | 烟尘、局部污染、冰面和寒冷进入场景 | 不增加生存数值系统 |

玩家不会因为打坏北闸一个控制柜就导致全星磁防护崩溃。任务只恢复地方港口能力。供热与冰质地基要有隔热和排水回收，不用漂浮建筑或无支撑平台掩盖地形关系。

## 天空与地图方向
冰脊港是虚构港口，位于朝木星的半球。工作点采用相对下木点向西约 74°、北纬约 10°的简化位置，不是已校准的 IAU 坐标或日期星历。

- 港图北上东右；敌方内陆货道在北与东北，泊位在东偏南，生活后勤与医疗在西南。
- 木星方位约 93°、仰角约 16°、视直径约 7.7°。潮汐锁定使其方位基本稳定，不设计日常周期升落。
- 当前一小时发生在漫长白昼后段；太阳暂设西方约 8°仰角，木星相位与同一太阳方向一致。
- 灰蓝或冷蓝大气、薄碎云与局部吹雪；木星经过大气有合理反差。太阳、天空散射与工作灯照明，木星不作探照灯。
- 三次观看：检修栈道第一次展开港景；北闸交接时帮助定位；尾声相同天空下，泊位灯和人员开始工作。

后续确定实际日期再校准星历。当前数值是统一制作的几何条件，不能写成做过科学模拟。

## 为什么等了十年
十年前，人类叛军夺权并获得外部势力支持；当前设定稿将外部支持具体化为外环财团，其称谓可以在正式剧本阶段调整。封锁、运输破坏、重载运力与护航体系重建，以及登陆保障，使地球联合政府无法迅速送达足够重装备。

当地反抗没有停下；医护、技工与居民持续维持生活。能修管线不等于拥有舰队、轨道制空权和重型运输能力。当前援军已经抵近，地面队伍必须保住接收人员、引导通信、泊位、装卸和安全进路。十年不是每十年才开放一次的神奇轨道窗口。

## 故事主线
十年前，陆建平将九岁的儿子陆闻川送向检修门，拾枪阻敌后死亡。年轻士兵周延完成一组居民撤离任务后被坍塌压住，看见未撤出的平民遭屠杀、班长赵启明被邵原处决。两个视点处于同一场灾难的不同位置；孩子已先离开主厅。

十年后，闻川是维修工和抵抗成员，长期追查邵原；周延成为战斗负责人，把自己存活当成必须偿还的责任。舰队抵近，两人约定共享可靠情报。闻川追踪仇人的经验帮助发现技工被强制撤走，救回罗敬等人并承诺保护家属。

周延担心追击分散人手，主动扣住邵原的转移预告。闻川从正常联络中发现违约，争执时说了不公道的话，却没有撂下工作。周延随后承认错误、共享完整信息，并采用孟齐的路线建议。

闻川得知邵原即将出发，也清楚追击可行却会占用护送与接防力量。罗敬在家人安全后自愿留岗；闻川收回伤人指责，选择履行护送承诺。孟齐因此能按时带队接防。

周延把阵位真正交出去，在同伴掩护中撤离，接受护具调整、休息并回复家人的消息。他已完成成长，也想继续活下去。此前已建立的敌军机动部队反扑；孟齐负伤，周延请求协作救援，随后受重伤、主动求援，两人均被送到医疗站。

孟齐存活，周延经救治仍死亡。闻川在悲痛中如实报告损失，接受郑铎帮助，继续接应。邵原逃入仍被占领的内陆；舰队开始进场。当地胜利打开全面光复的机会。

## 原作如何使用
完整小说约 30,202 个汉字（不含标点等的本次统计），十四章。它提供语气、人物日常和情感积累，不直接当一小时游戏对白。主线对白曾按约 3,600—4,600 汉字起步预算，仍须用录音和实机修剪。小说的旧天文与旧环境描写保留为历史文本，改编以本节设定为准。

# 03 · 人物、关系与成长

## 陆闻川
现在十九岁，序章九岁。本地维修工兼反抗军成员；陆建平与许岚的儿子。熟悉风机、门机、融冰排水、工服标识和检修通路。他已经会照顾熟人、完成工作，不能把开篇成年闻川写成只会愤怒的空白人物。

外在愿望是追上邵原，内在问题是怎样让自己的痛苦与眼前人的责任共存。长期追踪确实帮助识破撤港，因此复仇投入有现实价值；后段放弃机会才有损失。争执中他有理由反对隐瞒，也必须为“周延怕事”的不公指责负责。

成长证据依次是：继续履职；主动收回伤人话；在完整知情、追击仍有可能时留下护送；让孟齐按时接防；失去周延后如实报告并接受帮助。结尾不是突然宽恕邵原，也不是宣布彻底不恨。

呈现重点：第一人称手部与工具熟练度，观察工装和设备后的判断，忙碌中的短句，怒意下仍完成交接的动作。名字的隐约联想留给读者，不另写一段解释“闻川”的寓意。

## 周延
现在三十三岁，序章二十三岁。原驻军战士，赵启明的部下；被救后加入地下反抗，成为战斗负责人。他与闻川经许岚结识，关系从照看幸存孩子发展为共事。

他并非没有私人生活，而是总把休息、家人消息和自己的需要推后。幸存被他理解成欠死者、欠医护的债；不断承担风险和掌握全部信息让他感觉自己仍在偿还。隐瞒情报是这个习惯的错误表现，不能用“他早知大局所以没错”抹掉违约。

成长依次发生：承认隐瞒；交出可靠消息与不确定项；采用孟齐的专业建议；说出伤腿和换班需要；核实接防后离开阵位；接受护具调整与保护，回复家人、安排接下来想做的事。**S09／第十一章完成内在转变。**

S10 是以新方式行动：救孟齐时请求配合，中弹后主动报伤和求援。两人成功送达，周延仍因伤势死亡。文学上退场发生在成长完成之后，情节上死亡有已建立的军事原因。不能把成长改成独守到死、拒绝救援、突然新增必死任务，或只在遗言里说“我终于相信你”。

呈现重点：前期替别人检查、站在终端前过滤消息；后期把终端与位置让出来。接防队员实际占位、郑铎调整护具、孟齐掩护他走过通路，比独白更重要。

## 配角的独立职责
| 人物 | 自己想完成的事 | 关键行为与命运 |
| --- | --- | --- |
| 陆建平 | 保护孩子和正在撤离的人 | 普通维修工，抱怨和笨拙的日常也存在；先送孩子，后拾枪死亡，不追加秘密英雄身份 |
| 赵启明 | 组织居民撤离、让部下能判断 | 生前向周延授权；受俘后被邵原处决，信任在后来的换班中回响 |
| 许岚 | 完成护理和人员转移 | 闻川母亲、护理组织者，有自己的同伴与职责；死亡诊断由医师承担 |
| 孟齐 | 把人员送达，再完成接防 | 熟悉车辆、通路与交接；方案先被验证；腿伤后存活并继续治疗 |
| 罗敬 | 保护家人，判断自己还能做什么 | 九名港务技工中的重点人物；家属安全后自愿留岗；完成接收工作 |
| 邵原 | 撤走亲信与技工，破坏不能带走的能力 | 人类叛军指挥官；十年前暴行执行者；监控中确认撤离，结尾逃入占领区 |
| 郑铎 | 保持通信、协助接防和救援 | 真实接手职责、帮助周延、救援孟齐，最后补充闻川的汇报 |

沈玉芬是罗敬的妻子，原作还涉及孙辈与其他家属；不必新增大量具名近景角色。医师承担抢救决策与死亡告知。九名技工属于原作群体，北闸原型的七名工人是局部任务计数，不是把全片技工总数改成七人。

## 关系变化必须按顺序发生
| 阶段 | 两人关系 | 先有的证据 | 玩家能看见的变化 |
| --- | --- | --- | --- |
| 十年前 | 各自承受失去，还不是战友 | 父亲保护撤离者；班长信任部下 | 两条有限视点，不杜撰同时目睹全部事实 |

## 写作与配音的尺度
单段只提供当前人物能知道的信息。叙述和镜头避免全知反派视点。人物通过做事、停顿、打断、递物与让位表现关系，减少总结主题的台词。底部字幕显示“人名：内容”；每人声线可辨，战斗命令简短，关键争执与医疗对白在安全时段展开。固定结局不设计伪分支或假装治疗可以成功的小游戏。

# 04 · 战役与关卡设计

## 战役尺度与时长
保留“序章＋三个主关卡＋尾声”，以十二段叙事组织人物因果，以十组遭遇组织战斗。六组环境和二十一个旧空间编号是功能锚点，不能再被当成二十一个房间就能拼出的一小时。

| 单元 | 段落 | 行动主题 | 组织预算 |
| --- | --- | --- | --- |
| 序章：检修门 | S01—S02 | 两个视点经历同一场失守 | 约 7 分钟 |
| 第一关：占领区 | S03—S05 | 从日常生活进入被占领街区，营救后守住北闸前沿 | 约 17 分钟 |
| 第二关：通路 | S06—S08 | 修复通路与信任，保住护送和接防 | 约 17 分钟 |
| 第三关：下一班 | S09—S10 | 把位置交出去，在共同撤回中救人 | 约 13 分钟 |
| 尾声：进场之前 | S11—S12 | 承受失去，把接收工作做下去 | 约 6 分钟 |

这些是保留的叙事单元预算，不能强迫玩家等到对应时间。最近的战斗密度候选约为“战斗遭遇 39 分钟、非战斗操作及有内容移动 10 分钟、专门演出 11 分钟”，也未验证。旧版 30.5／16.5／13 分钟、每段绝对时码与低速推算仅供历史追溯；Mac 重建时必须重新分配、实测。

当前成人步行 2.1 m/s、奔跑 6.3 m/s。既有约 3.73 km 基础路径按全程奔跑仅约 9 分 52 秒，不能据此宣称一小时；也不能把移动中的战斗重复加进时间。敌人数、场地面积和对白长度各自都不能保证时长。

## 港区的空间关系
北、东北是敌方内陆公路与储料支线；东偏南是泊位和木星；西南是生活后勤与医疗。主线必须让玩家认得出这套地理。

| 区域 | 真实功能 | 与其他区域的关系 |
| --- | --- | --- |
| A 历史避难厅 | 公共等候、检修出口、防守侧 | 十年前独立场景；两个视点共用几何 |
| B 地下生活后勤 | 维修街、护理后勤、旧样本集合室 | 升井／坡路通往地表检修线与转运枢纽 |
| C 港务街区与接收中心 | 宿舍院、风雪门厅、控制室、设备层、检修栈道 | 接到北闸侧翼、转运系统，向泊位有视线 |
| D 北闸系统 | 前沿称重检查区、侧翼泵房储罐区、后线接防院 | 三次使用必须在不同局部战场展开；设备间与内门连接撤回线 |
| E 货运与桥群 | 转接门、货运坪、西侧桥、设备交叉口、安全岸路 | 接生活区、港务与医疗；敌方东北支线可进入交叉口 |
| F 旧检修库医疗站 | 登记、救治、等候安置 | 接护送与伤员转运；安全岸路回接收中心 |
| BG 东货场／泊位 | 邵原监控布景；远景舰队接近 | 是观看关系，不能误做玩家可直接冲过去的任务区域 |

需要保住的连接：B→C05 检修栈道→C02 门厅→C01 生活院／C03 接收中心；C03→E01 转接门→D02 设备间→D 北闸；D 后线→E03 交叉口→E02 西桥→F；F→E04 安全岸路→C03。东北敌方支线→E03 的路线提前展示，不能从已安全的医院背后刷敌。

旧地图把高程写作 Z，Three.js 通常用 Y 表示高程。新项目应在地图元数据中显式声明坐标约定，转换时不能把旧高度直接当成水平坐标。地图中地理北、世界轴、模型朝向也要一次说明。

## 三个主关卡怎样重新搭建
### 第一关：占领区
**进入。** 地下维修街和护理后勤有连续工作。经升井或沿基础绕行到露天栈道，转角展开冰脊、城市与木星；玩家可抬头观察，不用强制镜头。

**推进。** 背街观察押运异常，通勤检查口接敌；经短楼道或上下检修线接近宿舍后门；进入被军车征用的通勤广场与生活院。每个空间有自己的观察位、可退回的遮护和新的行动对象。

**结果。** 罗敬与家属进入安全交接位，孟齐解决运输。视点切到周延的北闸前沿，守住称重区与检查棚，使工人从独立后路撤回。短暂稳定后收到转移预告并隐瞒。

**地图要求。** 居民街区要有街坊深度和建筑侧面，北闸要有远处公路、入口集结区、近处展开区、玩家两处可换位火线以及工人安全后路。不能在一个空院站十几人充当整关。

### 第二关：通路
**进入。** 陆闻川修复转接门，病人实际通过，正常道路联络暴露隐瞒。双方在隔音设备间收枪争执，工作仍要继续。

**推进。** 切周延经侧翼检修台、泵房、储罐基础和内门退守；先处理一个方向，再应对已预告的新方向。采用孟齐路线后，车辆真正改变通过方式；公开完整情报。

**取舍与护送。** 接收中心显示家属到站，罗敬自愿留岗，闻川修复关系。监控证实邵原出发，追击与护送使用同一支有限力量。决定留下后，玩家清货运坪、第一桥头、侧平台与医疗桥头，短协作换车，NPC负责持续推车。孟齐带接防队实际返回北闸。

**地图要求。** 护送从一个区域推进到另一个区域；桥两端有完整作业区。通行安全状态逐段推进，后方可回撤补弹。监控与窗外实景明确分离；不生成“追击邵原”的假任务点。

### 第三关：下一班
**接防。** 周延守后线院；孟齐从此前清出的方向到达、占据交出的岗位、接上通信。玩家亲自穿过被队友掩护的撤回线。

**停顿。** 安全内门内坐下，接受护具调整，回复家人和谈一件任务后的小安排。这里让成长完成，不能有催促倒计时或看消息就受罚。

**撤回与救援。** 已预告的机动部队从内陆支线反扑。玩家先清交叉口近威胁；孟齐负伤，郑铎接近，玩家主动进入协作搬运。孟齐送入硬遮护后，明确进入固定演出；周延在尚未完全脱离的火线中负伤、报伤求援，两人沿已保住的路线送到医疗站。

**地图要求。** 前沿、侧翼、后线是三处不同的局部战场。救援地有设备基座、协作接力位、可见撤回硬遮护和先前建立的敌方入口。不能清场后凭空出现穿墙狙击手。

## 每张新地图至少给出什么
绘制具体场地平面与高程，标出：玩家进入／观察位、每一交火位及射界、可后退的补给位、NPC工作与等候位、敌方可见入口及隐藏集结、路口预告、转场、演出站位与镜头遮挡。箭头必须叠在实际地面、建筑、车辆和台阶上。验收同时看正常第一人称与自由观察，不能只用顶视图通线。

单次推进可从约 30—70 m 起步，主要室外战区约 80—180 m 纵深、60—150 m 横向组织；一关空间展开约 500—900 m×250—500 m，港区整体预留约 1.5—2 km×0.8—1.2 km。这些沿用的是设计量级，不是已实测尺寸。旧全片 2.2—3.2 km 路线预算和实际采样约 4.08 km 都不能锁定新地图；先有内容再定长度，背景远景不计入可玩面积。

# 05 · 玩法、演出与人类玩家体验

## FPS 的最低完整操作
| 功能 | 当前方向 | 接手时怎么核对 |
| --- | --- | --- |
| 移动 | 成人步行 2.1、奔跑 6.3、蹲行 1.35 m/s；无体力条 | 米制距离计时＋真人手感；不是 COD 实测参数 |
| 动作 | 骨骼素材按原速起步；移动倍率与动作播放独立 | 不把跑快变成动作快放，不把死亡慢放；步幅匹配后续靠合适动作与混合 |
| 鼠标 | 第一人称 Pointer Lock，ESC释放；恢复焦点清理旧输入 | 大角度连续转向、出入窗口、Alt/Command-Tab、重新点击不跳视角 |
| 瞄准 | 右键 ADS；瞄具、屏幕中心与弹丸方向一致，冲刺退出 | 正常比例下前后照门对齐，切姿态和换弹不漂移 |
| 跳跃 | 空格；自然重力 1.428 m/s²；现有起跳速度 1.65 m/s 仅为调试起点 | 头顶、台阶、坡面、移动中起落和落点碰撞；不把玩家弹出地图 |
| 射击与装填 | 左键射击、R换弹；少量主武器与手枪，最多两把为设计起点 | 动画、枪机／弹匣、发射和补弹时刻同步 |
| 蹲姿与交互 | C切换蹲姿，E情境交互；自由观察中的升降单独分配 | 多键并按、死亡、跳过、暂停后没有粘键或重复触发 |
| 自由观察 | 调试观察模式，明确暂停或隔离游戏控制 | 切回原人物位置与朝向，不改变任务和敌人状态 |
| 任务引导 | 世界目标可见；离屏时贴边箭头＋距离／方向，必要字幕回看 | 目标在背后、遮挡中、宽屏边缘都有可读提示 |

按键可以按 Mac 输入与测试重新映射，操作能力和输入隔离要保留。普通输入支持重新绑定是后续建议。儿童、剧情伤员、搬运状态有自己的限制，不影响正常枪战奔跑。浏览器快捷键与全屏要分别测试 Safari 和 Chromium；目前未在 Mac 验证。

## 弹丸与射击反馈
用户要求类似 PUBG 的有飞行时间弹丸。每发有位置、速度、发射时间，受当地重力与地球化大气阻力影响；碰撞沿上一位置到下一位置的线段扫掠，避免穿过薄物体。线段查询是飞行碰撞检测方式，不等于开火当帧直接命中全射程目标。

实际枪型、初速、阻力模型和伤害以后校准，不将某把原型冲锋枪写成最终制式武器。弹壳、落物与弹丸使用同一重力条件；牵引鞋只解释人员接地，不改变子弹下坠。视觉上不是每发都显示长发光激光线；可用有限曳光、命中尘屑、弹孔和声音表达射击。枪口不能穿墙后从墙后发射，近墙需阻挡或收枪处理。

后坐力、持枪摆动、镜头起伏分层，能降低晃动。换弹是完整片段加出入混合；稳定预备姿态与连续呼吸不要半段硬回循环起点。持枪手、握把、扳机、弹匣和枪机各自正确接触。

## 敌人与同伴
敌人至少能：观察、接近遮护、举枪射击、压制、换弹、短距离换位、丢失目标后寻找、受击、死亡。视觉与听觉有可解释边界；失去视线不能隔墙精确追踪。进场前有道路、声音或队友报告，不能在视野内生成；玩家提前到入口时推迟未进入的补组。

敌人分组入场，伤亡、任务进度和可读压力共同控制节奏。守点压力来自后续队伍接近、场内换位与任务进行，完成撤离或关闭入口后停止补兵。清得快可以更早推进；不设最后一人无敌、藏怪拖时间或无限刷兵填分钟。

队友有实际位置、射界和职责，会让开唯一通道与玩家枪口。技工修设备、医护转运、家属等待，再沿明确安全段移动。没有平民随机减员、隐藏救援倒计时或玩家友军伤害分支；对友方开枪给停火反馈。关键NPC不因玩家慢几秒而在背景死亡。

普通敌人死亡后终止AI与瞄准、完整倒地到地面、保持短时尸体，再淡出或在不可见时回收。原型约第12—15秒淡出是可调值，不是所有场景必须相同。周延的剧情死亡按医疗表演保留，不能套普通尸体自动消失。

## 容错与关卡完成
每次接敌有完整观察／恢复遮护，可看见下一处遮护和任务方向。近处换位先试约4—8 m暴露段，较长段给支援与分段遮挡；数值随6.3 m/s奔跑实测。玩家主要换位区争取2.4 m以上净宽，NPC不堵住后退口。低掩体看射界，高掩体恢复、装填和转向。

反复检查：打空一梭、错位换弹、冲过首个掩体、漏听报点、仰头看木星、退回补弹、在护送等待时离开、跳跃到边缘、换班后不立刻走。若多次失败集中在同一位置，先修地形、预告和敌人方向，再调伤害。

普通战斗死亡回最近检查点；剧情固定重伤不扣空生命条伪装失败。检查点恢复人物、弹药、门、任务、波次和已知信息一致，通常以少损失几分钟推进为目标；已见长对白可跳过。常规脱战回血不抹掉剧情旧伤和重伤。

## 演出与可操作叙事
全部使用同一引擎内场景、模型、光照和状态，区别只在控制权：
1. 作战操作：玩家控制移动与瞄准，队友短句并行，不强扭镜头看剧情。
2. 工作操作：可走、可看、可交互，角色收枪；重要长句安排在这里。
3. 协作操作：提示即将占用双手，玩家确认后搬运／递交；事前可退出。
4. 专门演出：固定角色动作，通常允许限幅观察；身体接触、坍塌、受击才短时接管。明确归还控制。

情境动作以人物实际站位、手部抓持和接触为前提。进入演出不能把人物瞬移到另一侧，镜头不能穿过自己头颅或模型。救援、父子抱撤、探视是高风险动作，应先用代理人体试接触，不等成品模型完成才第一次验证。

镜头设计先写“玩家此刻必须知道什么”，再确定人物距离、视线、遮挡和声音。前景设备不能挡住交接或受击；按玩家可能看左、看右、站偏的位置复核。重要事实可由动作、短语音和字幕补足，不靠频繁强制转头保证看到。

## HUD、字幕与声音
- 参考现代军事FPS的信息层级：准星中央；任务在侧上方；弹药与武器在右下；生命／受击反馈克制，方向可辨。具体视觉用自有设计。
- 底部中央显示“人名：内容”，近旁与无线电可加简短标识；与准星、交互提示分离。可调字号，关键指令可回看。
- 剧情人物与队友标记不穿过实体墙把所有信息暴露；任务点离屏指示仍能帮助找方向。
- 枪声、命中、危险方向和短报点有优先级；长争执不与多向交火重叠。建筑内外混响、遮挡与距离有变化。
- 九名具名人物声线可辨；配音文本按实机而不是朗读整部小说。免费或本地TTS尚未选型、安装或验收；交接不假定已经有成品声音。
- 医疗段保持工作声和停顿，死亡由医生明确告知，不全靠音乐或画面变灰暗示。

## 场景与视觉要求
写实尺度、冰质地形、隔热支座与清楚的建筑落地关系；墙体、窗带、管架和货物不互穿。近处掩体要能读用途和磨损，中景读清街区与工序，远景接冰脊、城市和木星。

原始网格、UV和材质层次优先保留。导入后排查材质组重复绘制、变换未应用、巨大包围盒、碰撞和可见几何不一致。雾、烟、景深、过暗曝光不能遮住问题或目标。实际第一人称画面与自由观察都要看，不能只看好看的固定镜头。

## 最低验证记录
每个切片至少留下：实际可操作入口；正常速度的视频或连续截图；玩家路径与碰撞复现；敌人入场／同时活动／实际射手／玩家和队友击杀分别计数；任务进度；死亡／重试；机器和浏览器信息；未解决画面问题。自动化可以证实某条路径通过，不等于人类玩家觉得成熟、自然或达到目标时长。

# 06 · 原创资产生产与复用

## 资产方向
用户已明确：可以使用自己制作的模型，并通过 Hyper3D、Tripo 补充原创资产，不必全部依赖开源模型。这里的 Tripo 对应此前赛事页面的服务，“Triple”按同一工具理解。

生产以关卡用途为先。适合生成的是角色外形、车辆、工业机具、生活物品与美术模块；地图拓扑、敌人路线、多人接触动画、碰撞和任务逻辑仍由制作过程设计。不要一次生成整张不可拆、没有实际通路的“漂亮港口”。

保留原始网格与资料，再建立运行用副本。材质转换、代码化装配和 Three.js 加载可以复用已有资产；不为了方便把所有复杂形体重画成立方体。来源与现有署名记录随复用对象保留，方便追溯和比赛说明。

### NG-VEH-01 · 北闸牵引维修车
寒冷工业卫星港口长期使用的电动牵引维修车，写实机械比例，四个承重轮、低重心底盘、拖挂钩与电芯检修盖，磨损黄灰涂装，轮胎和下部有盐霜与融雪痕，维护工具合理固定。车长约3.8米、宽1.8米、高1.65米，车体应能作为成年人完整遮护，允许玩家从两侧绕过。单一车辆资产，完整背面与底部，不带场景地台，不把轮胎与地面融合，不生成枪械或人物。优先PBR；门盖、轮组和车体作为可识别部件；标牌留空由后期统一制作。参考图使用本项目自有设计。

### NG-MCH-01 · 过滤维护机组
地球化港口的可移动空气滤芯维护设备，有稳定底座、金属护架、可抽出的滤芯模块、服务面板与管道接口。写实工业设计，尺寸约2.4×1.4×1.8米，冷灰壳体、深色橡胶、局部旧黄色安全标识，保养痕迹与更换过的零件可见。用途是工人收尾检修，机体一侧提供遮护、另一侧保留操作空间。独立资产、无人物、无地台、无烘焙背景；面板和滤芯需要后续可拆，文字由后期添加。

### CH-ZHOU-01 · 周延基础体
三十三岁东亚男性，长期在寒冷工业港工作的抵抗军战斗负责人，写实人体比例，疲惫但警觉，保暖工作层外混搭旧式军用护具，面部清晰、护目镜可置额部，膝部有可辨护具。中性站姿或标准A姿，双臂与躯干留隙，五指可辨，完整鞋底，不持枪、不含场景，不把背包带与手臂融合。外观参考同一张人物设定图，前后衣物结构一致。骨骼、握枪、面部表演与伤势状态另行制作，不能把基础生成标成角色已完成。

### WP-CARBINE-01 · 短卡宾枪
原创近未来短卡宾枪，写实机械与握持比例，便于室内和港口近中距作战；清晰的前后瞄具、枪口、弹匣接口、抛壳口、枪托和双手握持空间。单独武器，无手臂、无环境、无发光弹道。弹匣和枪机需要可独立控制，贴图不烘焙人物或背景。枪长和握把尺度在Blender按人体校准，瞄具对齐后再导入第一人称测试。

## 生成结果到 Three.js
1. 保存生成原件、使用的参考图／提示词、工具与任务ID、费用记录；下载实际文件，临时链接不能当作长期资产。

## 第一次接手
将本包放在选定的Mac项目目录下，例如 `docs/product-handoff/`。新项目实际根目录由用户选择，不照抄Windows盘符、旧本地服务端口或浏览器配置。先读START_HERE与Mac提示词，检查当地仓库、工具和已有工作。

## 制作顺序
| 次序 | 产出 | 完成时应有的实物证据 |
| --- | --- | --- |
| 1 理解与选定切片 | 复述人物因果和产品边界；选一段实际关卡作为起步 | 来源清楚的任务说明、画面目标、需要的资产；未选比赛范围时先给推荐 |

| 3 一段完整遭遇 | 优先重建北闸E04的四阶段、人物路线和任务结束 | 工人真实到达、敌人可读入场、队友接替、撤回和收束对白 |

# 09 · 原型经验与已有证据

## 用户实际反复指出的问题
| 问题 | 暴露的设计／实现错误 | Mac版本怎样避免重演 |
| --- | --- | --- |
| 整个地图像一个关卡 | 用连接线和小房间替代完整行动区域 | 三关各有进入、接近、交战、穿越、退出 |
| 路线图难以理解 | 动线离开实际建筑与地形单独画 | 在具体地图上标位置，并用实际人物实走 |
| 动作僵硬、走得过慢 | 时间轴驱动演出，缺真实动作和内容 | 成熟动作库、正常速度，时长由遭遇和结果支撑 |
| 跑快后身体动作也快放 | 把移速倍率耦合到动画与镜头 | 位移和动画独立，素材原速＋合适步幅 |
| 对话与射击混在一起 | 同时索取阅读、听觉和瞄准注意 | 短报点并行，长争执／取舍在安全间隙 |
| 缺ADS、跳跃、离屏指引 | FPS基础能力没组成完整输入系统 | 在美术扩展前联测多键、锁鼠标、瞄准、跳跃、重试 |
| 鼠标转大角度跳视角 | 窗口边界与重新进入处理错误 | Pointer Lock与失焦清理，正常真实鼠标回归 |
| 死者直立、僵在原地 | 伤害／AI／动画状态不一致 | 原速倒地、停止行为、落地、保留后回收 |
| 敌人排队冲出来挨打 | 只做进场轨迹，没有遮护与作战职责 | 真实入口、展开、换位、瞄准、装填、退守 |
| 水泥台子与环境不搭 | 功能性灰盒直接当最终美术 | 让生产生活物件承载遮护和叙事 |
| 建筑浮空、人物穿模 | 变换、地形、动画和碰撞未统一 | 检查落地、分件、实际网格碰撞和人物接触 |
| 景物遮住该看的行为 | 只按一个导演视角摆场景 | 真实第一人称多站位观察，保证关键事实可读 |
| 文档说得好、交付不成立 | 把设计预算和自动走线当成成品证明 | 同一可玩片段一起验收操作、人物、画面、声音和任务 |

## Mac上原生初始化的步骤
1. 读取Mac当前项目自己的入口说明，确认工作目录、仓库状态、当地Nativue Skill、CLI或checkout。保持本机已有工作和配置。
2. 如果只发现Skill，报告能力边界，继续用本包完成产品接手；不要声称服务已连接。是否安装CLI按当时用户授权与项目规则处理。
3. 在用户选择的实际项目中，按已安装版本help运行init、doctor、scan、analyze；检查已有.nativue配置，不覆盖旧状态。
4. 若生成analysis-request，使用它的真实inputId与索引文件产生语义分析，证据路径必须出现在那份索引中；文档未被索引时，保留本包作产品背景，不虚构代码证据。
5. 通过CLI写入／导入，不手改ledger绕过版本检查；可用时启动serve。没有启用runner时不承诺无人值守更新。
6. .nativue为本机运行资料，不随公共模板分发；远程同步、账户配置和跨机器锁不自动继承。

这些是根据已读Skill的操作顺序描述，具体参数按Mac安装版本确定；本包不提供伪造inputId或硬编码安装路径。
