# 现行木卫三版本 V3：演出问题梳理

2026-10-28。项目沿用《重返木卫六》目录名，场景设定已转为木卫三。本轮只新增复核记录、测量数据和截图。

## 结论

用户提出的慢走拖时长、剧情与射击混淆、字幕表达不合适、人物穿模、建筑悬空、重要内容被遮挡，均找到了对应实例。

最主要的问题是：人物位置、交火、台词、镜头和环境事件分别按时间推进，彼此没有形成足够可靠的行动因果。于是字幕说救人，镜头还在看射界；角色站在墙后，却被当成射击目标；时间到了敌人就倒下；同一秒两个角色进入同一个位置。仅替换动作资源、调高速度或增加材质精度，都无法独立解决这些问题。

当前 60 分钟是十二段预设时间的总和。主角沿脚本路径运动；第一人称可以环顾、试射，WASD 控制自由观察镜头。敌人倒下和段落结束主要依赖时间，命中没有决定战斗何时完成。因此，这个版本尚不能据此证明有一小时的可玩内容。

## 核查范围与数据口径

- 对十二段主角运动按 0.5 秒采样；核对十二段关键画面、25 个射击停点和对话/救援的视线。
- 对 S05 向建筑射击、S07 镜头穿入队友等关键问题做了选段 1× 播放复现。本轮没有宣称以原速看完完整一小时。
- 下文时间均为**段内时间**，坐标均为 **Three.js 世界坐标 (x,y,z)，单位米**。原始策划数组有不同轴顺序，不能直接照抄。
- 低于 0.7 米/秒使用用户给出的参考值作筛查；它不是本轮测得的人类平均步速。
- “位置基本不变”指采样速度小于 0.05 米/秒，包含掩护、对白、受困和病床停留；“低速移动”指 0.05–0.7 米/秒。两者不能直接等同于应删除的时间。
- 人物距离筛查用于找疑点。以下明确标注的穿模样例结合了画面；未逐一视觉核实的点单列为候选。

后续应先测“正常行动速度下，确实存在的移动、交战、操作和剧情各占多少时间”。剩下的缺口要由有作用的交战与任务内容补足。没有必要把当前每一段的分钟数都保住。

### 5. 字幕有名字，但形式仍不符合要求

当前默认 1280×720 画面中，字幕框底部位于 y=527，离画面底边约 **193 像素**；姓名为 **11 像素、独占一行**，内容为 16 像素，位于大块控制台上方。已有姓名，不应误报为“完全没有人名”。

沉浸模式能降低字幕位置，但两种显示模式尚未统一。后续应采用稳定的底部安全区和清晰的 **“人名：内容”** 关系，并区分现场对白、无线电和任务状态。可用方向示意：“郑铎：抬稳，往掩护后面走。”具体字号、行宽与安全边距需要在游戏视口中检视。

当前字幕只按时间显示数秒，人物配音尚未承担对白；长时间没有字幕、没有动作变化的画面更显空。不能只靠把字幕常驻来弥补演出内容不足。

### S01 检修门 · 03:00 · 年幼的陆闻川

**这段需要成立的事：**父亲把孩子交给撤离者，回身拾起牺牲战士的枪，最终倒下。观众应看懂保护、分离和死亡的因果。

**后续处理方向：**保留孩子的恐惧、回望和父亲诀别；用有对象的动作承担停顿。拾枪、护住通路、受击和孩子被带走要连续可读。空路上的匀速挪动应压缩。
