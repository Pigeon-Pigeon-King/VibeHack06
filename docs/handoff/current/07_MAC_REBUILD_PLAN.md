# 07 · Mac 接手与重新制作顺序

## 第一次接手
将本包放在选定的Mac项目目录下，例如 `docs/product-handoff/`。新项目实际根目录由用户选择，不照抄Windows盘符、旧本地服务端口或浏览器配置。先读START_HERE与Mac提示词，检查当地仓库、工具和已有工作。

当前原项目不是Git仓库，本包没有提交SHA；新项目应保留真实的开发历史，不给旧资料伪造新作者或新完成时间。不要把源机的AGENTS.md、凭据、缓存、.nativue运行态或系统配置复制到Mac生效。

## 制作顺序
| 次序 | 产出 | 完成时应有的实物证据 |
| --- | --- | --- |
| 1 理解与选定切片 | 复述人物因果和产品边界；选一段实际关卡作为起步 | 来源清楚的任务说明、画面目标、需要的资产；未选比赛范围时先给推荐 |
| 2 射击基础 | 在有地面、墙、坡和门的测试场整合控制、枪械、弹丸、敌人和重试 | 正常键鼠可玩，移动／ADS／跳跃／大转向／装填／死亡均能复现 |
| 3 一段完整遭遇 | 优先重建北闸E04的四阶段、人物路线和任务结束 | 工人真实到达、敌人可读入场、队友接替、撤回和收束对白 |
| 4 代表性美术 | 同一切片完成近中远景、实物掩体、材质、光照与声音 | 正常第一人称和自由观察都有可信画面；不是只放置灰盒 |
| 5 叙事风险验证 | S08知情取舍；S09交接→S10协作→S11医疗短片段 | 玩家理解因果；多人接触、固定伤情与普通失败明确分离 |
| 6 扩展完整战役 | 三关各自完整推进链，接通十二段 | 各关真实地理与任务连续；不是复制同一小场地刷更多轮 |
| 7 全流程核算 | 真实首通、失误恢复、画面与性能记录 | 55—70分钟目标重新测量；列出仍未解决的问题 |

以上是后续建议，不是已安排的开发工期。若比赛只交一个切片，应由用户明确选择范围；不能把切片通过写成一小时战役完成。

## 建议的模块职责
Three.js已经确定。其他库、构建工具和物理实现先检查Mac上已有项目再选择，不为套某个模板放弃既定体验。

| 模块 | 负责什么 | 需要与谁一致 |
| --- | --- | --- |
| 应用与加载 | 启动、场景切换、暂停、错误可见、资源释放 | 关卡／检查点、渲染资产 |
| 输入与玩家 | Pointer Lock、走跑蹲跳、ADS、交互、自由观察隔离 | 碰撞、枪械、控制权 |
| 战斗 | 武器、弹药、飞行弹丸、伤害与反馈 | 物理场景、人物状态 |
| 人物 | 动作混合、身份、受击、死亡、身体协作 | AI、演出、道具 |
| 遭遇 | 入场、角色分工、掩体选择、撤退、有限增援 | 导航、任务事实 |
| 任务与存档 | 人员实际到达、设备状态、检查点、信息范围 | 所有任务参与者 |
| 剧情演出 | 控制权、站位、身体接触、字幕、跳过终态 | 玩家、人物、任务 |
| 世界与呈现 | 地形、建筑、PBR、天空、灯光、音响和HUD | 物理／导航与美术方向 |
| 资产工具 | 原件→修整→GLB→运行验证；生成任务与下载 | 项目外的授权服务，不进入浏览器凭据 |

参考实现只用于解决具体技术问题。Three.js官方FPS／动画／天空例子、已有模板的控制器或AI可以研究；整套模板是否适合必须在实际动作中验证。当前没有发现一个复制后就能自然实现这部战役的已验收底座。

## Mac 首次可玩验证
- 在目标Mac确认硬件、内存、系统、浏览器及实际分辨率。1080p／60fps是目标，不是已有结果。
- 使用本机适用的键位，检查Command/Control组合、窗口失焦、缩放、鼠标锁定和右键。
- 生成服务只通过已授权的工具进程访问。API密钥不进入public目录、网页脚本、演示构建或提交；本包不含凭据。
- 原件与运行版分开，已有用户文件不被自动覆盖；任务数据使用项目相对路径。
- 现场试玩要能重新开始；状态、人物和补给重置一致。展示操作与游戏操作分离，不能靠自动脚本冒充可玩流程。
