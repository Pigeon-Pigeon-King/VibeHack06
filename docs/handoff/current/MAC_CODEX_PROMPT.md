请接手《重返木卫三》的产品构思与后续开发。本目录是上一台电脑整理的产品资料，不是已经完成的比赛作品或可直接迁移的游戏底座。

先阅读START_HERE.md，再读01—10分册；SOURCE_INDEX.md说明来源和优先级，references/novel_original.md是完整十四章原小说。需要人物语气与细节时回原文，不要只依据摘要。data/有十二段流程、遭遇预算、资产和任务建议；architecture/product-graph.json是Nativue方法下的产品关系参考，不是原生运行态。

必须理解：
- 固定线性FPS，陆闻川与周延双视点；约一小时完整产品，序章、三个完整主关卡、尾声。
- 地球化木卫三有可呼吸的寒冷室外；自然重力1.428m/s²，木星约7.7°、当前东偏南仰角约16°，不是每到一个镜头换位置。
- 人类叛军有外部支持，十年等待由封锁与运力重建解释；当前只争取援军进场，邵原逃离。
- 闻川在完整知情、追击确实可行时留下护送；他与周延在死亡前修复关系。
- 周延先公开情报、交出阵位、接受保护、表达继续生活的愿望，后协作救人、受伤求援、救治失败。孟齐获救存活。不可改成独守求死或玩家操作失败。
- 最终用Three.js。具体地图和实现可重做；自制、Hyper3D、Tripo和已有素材混合生产，保留有用网格、UV、PBR、骨架和动画。
- 最新普通步行2.1、奔跑6.3、蹲行1.35m/s，动作原速起步且与位移解耦；有限飞行时间弹丸、ADS、跳跃、稳定鼠标锁、离屏目标、正常倒地和尸体回收都需要落实。
- 不用慢走、动画慢放、无限刷兵或固定播放时间填满流程。敌人有真实入口与掩体，目标和实际人物到达控制阶段。
- 用户多次不满意漂浮／穿模建筑、僵硬动作、低质材质光照、无用途水泥掩体和只画箭头不做实际地图。需要正常第一人称可玩与自由观察两种证据。
- 所有剧情在同引擎内处理，控制权交接清楚，底部字幕“人名：内容”；长对话避开密集枪战。

在Mac本地先检查当前项目规则、仓库、工具、浏览器与Nativue能力。若已有相关状态，读取后继续；不要照抄旧Windows路径、端口、AGENTS、账号配置或运行缓存。源项目没有Git仓库，因此包里没有可引用的提交SHA。不要编造运行、C评审或用户验收记录。

本次接手先给出简明的产品理解、版本差异、可复用资料与下一项有实际交付物的任务。对已明确的创作方向直接沿用，不重新逐项问我。随后按我在这个会话指定的制作范围执行；如果还没有选定比赛范围，建议以北闸四阶段为首个可玩切片，清楚标明它只是完整战役的一部分。

Nativue可用时按当地Skill通过CLI扫描真实项目、生成真实inputId并建立架构；不可用时如实说明，继续用包内参考理解产品，不手写伪造ledger。后续多代理协作只在本会话明确选择该模式后进行。

Hyper3D／Tripo的接入和费用以实际账号为准。先检查官方能力与版本；Tripo文档在2026-10-30提示v2 API将于10月31日停用，避免旧教程。生成前按我已给出的范围与预算执行，密钥不贴到对话或浏览器脚本中，不自动消耗未经授权的额度。

保留前期构思、旧资产与比赛中新实现的真实来源。没有依据时，不宣称比赛允许所有预制资产，也不通过重建仓库改写已有工作的时间。

第一次回复要让我看出你理解这个游戏，然后进入具体工作。不要把重新制作关卡理解成推翻既定人物故事，也不要把现有原型误当成成熟FPS质量标准。
