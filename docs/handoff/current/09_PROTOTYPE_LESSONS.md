# 09 · 原型经验与已有证据

## 用户实际反复指出的问题
| 问题 | 暴露的设计／实现错误 | Mac版本怎样避免重演 |
| --- | --- | --- |
| 整个地图像一个关卡 | 用连接线和小房间替代完整行动区域 | 三关各有进入、接近、交战、穿越、退出 |
| 路线图难以理解 | 动线离开实际建筑与地形单独画 | 在具体地图上标位置，并用实际人物实走 |
| 动作僵硬、走得过慢 | 时间轴驱动演出，缺真实动作和内容 | 成熟动作库、正常速度，时长由遭遇和结果支撑 |
| 跑快后身体动作也快放 | 把移速倍率耦合到动画与镜头 | 位移和动画独立，素材原速＋合适步幅 |
| 对话与射击混在一起 | 同时索取阅读、听觉和瞄准注意 | 短报点并行，长争执／取舍在安全间隙 |
| 缺ADS、跳跃、离屏指引 | FPS基础能力没组成完整输入系统 | 在美术扩展前联测多键、锁鼠标、瞄准、跳跃、重试 |
| 鼠标转大角度跳视角 | 窗口边界与重新进入处理错误 | Pointer Lock与失焦清理，正常真实鼠标回归 |
| 死者直立、僵在原地 | 伤害／AI／动画状态不一致 | 原速倒地、停止行为、落地、保留后回收 |
| 敌人排队冲出来挨打 | 只做进场轨迹，没有遮护与作战职责 | 真实入口、展开、换位、瞄准、装填、退守 |
| 水泥台子与环境不搭 | 功能性灰盒直接当最终美术 | 让生产生活物件承载遮护和叙事 |
| 建筑浮空、人物穿模 | 变换、地形、动画和碰撞未统一 | 检查落地、分件、实际网格碰撞和人物接触 |
| 景物遮住该看的行为 | 只按一个导演视角摆场景 | 真实第一人称多站位观察，保证关键事实可读 |
| 文档说得好、交付不成立 | 把设计预算和自动走线当成成品证明 | 同一可玩片段一起验收操作、人物、画面、声音和任务 |

这些反馈属于产品验收依据，不表示所有旧缺陷在所有章节都已修好。逐项检查新实现，不复制旧原型的外观和限制。

## 北闸V2可以提供的证据
已有记录：2026-10-30，Windows测试Chromium，Three.js r180，1920×1080；运行标识 northgate-v2-1793362953765。详情见随包的 [PLAYTEST记录](references/northgate_playtest.md) 与 [场地说明](references/northgate_scene.md)。

- 四阶段8＋12＋10＋14，共44名敌人，同场存活上限8；七名工人实际撤离。
- 一次完整回归记录41名敌人死亡（其中玩家29），3名幸存者在任务交接后撤退；任务不要求逐一杀完远处残兵。
- 记录640枚弹丸、298次场景命中、253次人物命中，50次掩体选择、未记录寻路失败。
- 记录稳定步行2.10、奔跑6.30、蹲行1.35m/s，以及跳跃、ADS开火、多键装填、转向、目标边缘标识、重新开始。
- 41名死亡角色完成原速倒地与淡出；补充检查从正面奔跑被岗亭墙挡住，横移能绕过。
- 曾发现一个工人起点被旧补给箱挡住；移动补给并更新设备加入后的导航后，重新完整运行。

这些结论是**既有测试文档的记录**。本次交接没有重跑游戏。记录中的224.75秒包含输入测试和自动瞄准，不是真人首通，不是全战役计时；“PASS”不证明成熟商业FPS观感或Mac性能。用户尚未对该版本提交完成验收。

## 仍未完成
全战役真人试玩、完整三关的最终画面、Mac浏览器性能、成熟的多人接触和面部表演、录制配音、死亡地形自适应／布娃娃，以及统一的全片角色资产。远景仍粗，北闸近处提升不能代表其他区域。原型队友和工人无死亡分支，这是当前保护机制，不能宣传成复杂可变战局。

## 能取用但不应照搬的技术
- Three.js官方FPS示例中的Capsule／Octree思路，用实际场景三角面碰撞并分小步更新；不将碰撞几何与视觉网格混淆。
- 官方骨骼混合、天空示例用于具体机制；完整FPS模板用于控制、状态拆分和动作组织参考。
- 旧Godot工业网格保留材质映射后适配到Three.js；不能只看文件扩展名认定不可用。
- 旧导入曾有容器主体、门板和材质子网格分开保存的问题；隐藏其中一块会留下“幽灵”残片，复用时需逐节点检查。
- 生成和导入完成不代表动画、碰撞、导航、LOD和任务状态完成。

代码参考入口：[Three.js官方示例](https://github.com/mrdoob/three.js/tree/dev/examples)、[slop-newyork](https://github.com/mrdoob/slop-newyork)、[既有FPS模板调研](references/fps_research.md)。这是研究线索，不是已批准直接套用的整套底座。
