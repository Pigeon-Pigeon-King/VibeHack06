# 06 · 原创资产生产与复用

## 资产方向
用户已明确：可以使用自己制作的模型，并通过 Hyper3D、Tripo 补充原创资产，不必全部依赖开源模型。这里的 Tripo 对应此前赛事页面的服务，“Triple”按同一工具理解。

生产以关卡用途为先。适合生成的是角色外形、车辆、工业机具、生活物品与美术模块；地图拓扑、敌人路线、多人接触动画、碰撞和任务逻辑仍由制作过程设计。不要一次生成整张不可拆、没有实际通路的“漂亮港口”。

保留原始网格与资料，再建立运行用副本。材质转换、代码化装配和 Three.js 加载可以复用已有资产；不为了方便把所有复杂形体重画成立方体。来源与现有署名记录随复用对象保留，方便追溯和比赛说明。

## 工具与接入：2026-10-30 核对
| 工具 | Mac Codex 中的使用方向 | 本包状态 |
| --- | --- | --- |
| Hyper3D / Rodin | 官方远程 MCP，可在授权后提交、查询并取得下载；需要精确参数时使用项目侧 REST 工具 | 已核对文档，未连接账号或生成 |
| Tripo | 官方文档提供 Codex 插件；也可用官方 SDK / API 做可记录的资产任务 | 已核对文档，未在本机或目标 Mac 安装、登录、生成 |
| Blender | 调整比例、分件、法线、UV、骨架、碰撞和导出；与生成服务配合 | 原 Windows 环境有 Blender；Mac 安装情况未知 |
| Three.js | 最终浏览器运行与素材验收 | 框架已确认；具体依赖版本在新项目中确定 |

Hyper3D MCP 地址为 `https://api.hyper3d.com/api/mcp`，授权时选择实际计费工作区。优先使用 Mac 当时已有的官方接入能力，不把“Skill 文件存在”当成“服务已连通”。[官方 MCP 说明](https://hyper3d.ai/features/mcp)

Rodin REST 为异步提交、状态查询、下载三步；状态查询使用返回的 subscription key，下载使用任务 uuid，不能混用。密钥留在受控的本地工具进程，任务结果不明时先查状态，避免重复提交。[官方 Quick Start](https://docs.hyper3d.ai/en/get-started/quick-start)

Tripo 官方 Codex 插件文档说明支持 Mac 与浏览器授权。插件是否出现在目标 Mac 的目录、账号权限与额度，需要现场检查；不是本包已验证的安装结果。[官方插件说明](https://developers.tripo3d.ai/en/docs/codex-plugin)

**接入时注意版本：** Tripo 官方 SDK 文档提示 v2 API 计划于 2026-10-31 停用，Python 0.x 不再适用；该页列出 API v3、Python SDK 1.0.0 等入口。Mac 制作发生在这一时间段，应以当时官方文档核对 SDK、账号区域和模型版本，不能把 API v3 与模型版本名称混为一谈。[官方 SDK 文档](https://developers.tripo3d.ai/en/docs/sdk)

生成花费与套餐以已授权账户为准。本次不预设会员已兑换、Studio 与 API 积分通用或已获得无限生成额度。拿到明确预算后按资产清单分批执行，不静默循环重抽。

## 第一批资产建议
先用少量代表对象建立统一质量，优先解决北闸“都是空白方块”的问题。表中是设计需求，不是已有成品清单。

| 优先 | 资产 | 叙事与玩法职责 | 需要拆出的部件／状态 |
| --- | --- | --- | --- |
| P0 | 港区牵引维修车 | 停在称重线边等待换电芯，有轮胎、拖钩、支架；形成完整遮护与侧绕线 | 车体、轮组、检修盖、挂接部；正常／停用 |
| P0 | 空气滤芯维护机组 | 撤离前工人正在收尾的设备；让保护对象有具体工作 | 壳体、滤芯架、服务面板、管接口；停机／运行 |
| P0 | 货物与托盘家族 | 延期备件、被征用物资、封签和绑带，构成低／高遮护组合 | 货物、托盘、绑带、可替换标牌；不生成所有文字 |
| P0 | 称重亭与查验门架 | 北闸首个可读地标，合理门窗与车辆净空 | 墙板、门、窗、灯、栏杆、称重台；关／开 |
| P0 | 周延、陆闻川与基础敌兵 | 可辨身份和写实人体，能接入动作库 | 人体、服装层、护具、手部；武器单独 |
| P0 | 第一人称武器／手臂 | 稳定握持、ADS、射击、完整换弹 | 弹匣、枪机、照门、枪口与双手控制 |
| P1 | 转运车／担架 | 护送、换车、救援与医疗贯通 | 轮组、把手、床面、固定带；坏轮状态 |
| P1 | 港务控制台与终端 | 情报、共享、监控与接收有不同内容 | 屏幕、按键、开关；贴图与界面由程序制作 |
| P1 | 其余具名人物与群众 | 罗敬留岗、许岚护理、孟齐接防等 | 共用骨架＋身份变化；儿童独立比例 |
| P1 | 冰脊、隔热地基、管线与街坊模块 | 连续地表、生活环境和工程用途 | 可拼装接缝、坡面、支座；内外分层 |
| P2 | 吊机、换热塔、泊位与运输舰轮廓 | 中远景定向与结尾反馈 | 近景可交互部件另做；远景低成本 |

建议先出一辆牵引车、一套货物、一套维护机组、一名角色和一套武器手臂代表样。它们进入真实第一人称照明与战斗后，再决定批量生成的外观和精度。

## 所有生成任务共用的资产简报
每个任务写明：资产 ID、出现关卡、原本用途、现实尺寸、玩家最近观看距离、主轮廓、材质、使用痕迹、必需分件、是否要骨架、已知动作、输出目标、参考图与任务ID。不要仅写“高质量科幻模型”。

提示词范例（可直接改；输出能否满足尺寸／分件须在 Blender 检查）：

### NG-VEH-01 · 北闸牵引维修车
寒冷工业卫星港口长期使用的电动牵引维修车，写实机械比例，四个承重轮、低重心底盘、拖挂钩与电芯检修盖，磨损黄灰涂装，轮胎和下部有盐霜与融雪痕，维护工具合理固定。车长约3.8米、宽1.8米、高1.65米，车体应能作为成年人完整遮护，允许玩家从两侧绕过。单一车辆资产，完整背面与底部，不带场景地台，不把轮胎与地面融合，不生成枪械或人物。优先PBR；门盖、轮组和车体作为可识别部件；标牌留空由后期统一制作。参考图使用本项目自有设计。

### NG-MCH-01 · 过滤维护机组
地球化港口的可移动空气滤芯维护设备，有稳定底座、金属护架、可抽出的滤芯模块、服务面板与管道接口。写实工业设计，尺寸约2.4×1.4×1.8米，冷灰壳体、深色橡胶、局部旧黄色安全标识，保养痕迹与更换过的零件可见。用途是工人收尾检修，机体一侧提供遮护、另一侧保留操作空间。独立资产、无人物、无地台、无烘焙背景；面板和滤芯需要后续可拆，文字由后期添加。

### CH-ZHOU-01 · 周延基础体
三十三岁东亚男性，长期在寒冷工业港工作的抵抗军战斗负责人，写实人体比例，疲惫但警觉，保暖工作层外混搭旧式军用护具，面部清晰、护目镜可置额部，膝部有可辨护具。中性站姿或标准A姿，双臂与躯干留隙，五指可辨，完整鞋底，不持枪、不含场景，不把背包带与手臂融合。外观参考同一张人物设定图，前后衣物结构一致。骨骼、握枪、面部表演与伤势状态另行制作，不能把基础生成标成角色已完成。

### WP-CARBINE-01 · 短卡宾枪
原创近未来短卡宾枪，写实机械与握持比例，便于室内和港口近中距作战；清晰的前后瞄具、枪口、弹匣接口、抛壳口、枪托和双手握持空间。单独武器，无手臂、无环境、无发光弹道。弹匣和枪机需要可独立控制，贴图不烘焙人物或背景。枪长和握把尺度在Blender按人体校准，瞄具对齐后再导入第一人称测试。

## 生成结果到 Three.js
1. 保存生成原件、使用的参考图／提示词、工具与任务ID、费用记录；下载实际文件，临时链接不能当作长期资产。
2. Blender 先核对轮廓、比例、背面和底部。多面粘连、缺零件、模糊脸、手指、贴图幻觉先修复或重做；不把它们藏在暗光里。
3. 用米制统一尺寸，明确原点、朝向与可动部件；保留有价值的原网格、UV、法线与材质槽。运行版另存，源件不覆盖。
4. 生成角色与动画分开验收：骨架、权重、重定向、脚底接地、转身、持枪、换弹和死亡；A姿或T姿不等于已绑定。救援与抱撤是多人协作动作，需要专门校准。
5. GLB / glTF 2.0 作为运行交付主路径；使用可被 Three.js 表达的PBR。复杂 Blender 节点需要烘焙或改写，保留色彩空间、法线方向与ORM通道正确性。
6. 制作适合用途的碰撞体、导航边界和LOD；可见门的开闭与碰撞状态同步。多LOD不能同时叠在同一位置显示。
7. 在实际场地导入，测第一人称最近距离、材质、阴影、碰撞、弹道遮挡、动画与加载成本。按目标Mac配置调整；不以生成服务的预览图完成验收。

面数、纹理和合批采用实测预算：主角与第一人称比远景优先，远景轮廓比细密螺丝优先。没有依据为所有资产统一规定同一面数，或为整个Mac系列承诺同一帧率。
