# Blender 场景制作与交付说明

本文件补充现有制作规划中的三维生产要求。下列尺寸是白盒起点，不是原文事实；可以按检查结果调整并记录。

## 一、场景清单

| 场景编号 | 子空间与职责 | 必要状态 | 段落 |
| --- | --- | --- | --- |

## 二、连通与剧情视线

ENV-A 为十年前独立地点，不与现时地图硬连。现时 ENV-B 通向港务区；ENV-C、ENV-D、ENV-F 由 ENV-E 连通。建立带编号的俯视图，标出门、主线方向、人员等候点和故事段落。

- A02 从儿童已进入的检修通道仍能短暂看见父亲。A03 的周延能看见班长受困的位置，同时与儿童幸存位置区分。用遮挡和眼高实际验证两条视线。
- D01 有至少两个相通掩护位置，分别能读懂车道、储料与维修通路；D02 位于后侧并可从 E01 抵达；D03 是交接后能短暂调整护具的受保护空间。
- S08 使用 E02 的车队狭口和安全停候区；S10 的反扑发生于 E03，再接回已保住的转运段。损坏与遮挡不能抹掉已完成的护送成果。
- F02 容纳周延、医师、护理人员、陆闻川探视位和担架进出。F03 保留受伤孟齐的位置，使其存活和继续治疗可见。登记、救治、等候区均有具体用途。
- F 到 C 的尾声路线是一条清空的短连廊。用摄像机模拟步行长度，35—45 秒为规划起点，最终时间需在引擎验证。
- BG-01 只通过终端监控摄像机呈现，不在可玩区域开一个能向邵原开枪的窗口。为终端留可单独替换的屏幕面及相机标记。
- BG-02 是运输舰接近的远景，不扩展为可登陆探索的舰船或完整太空战场。

## 三、尺度与工程组织

使用 Metric，1 Blender Unit = 1 米，Z 轴向上。共享原点和朝向由首轮白盒决定，写入 README。各环境在总览工程中保持实际连接位置；独立保存时记录变换，避免导入后无法对齐。

起始检查值：成人代理约 1.75 米高、站立眼高约 1.65 米；九岁儿童代理约 1.30 米高、眼高约 1.20 米。相机视野统一并记录横向或纵向定义。以上可依角色设定合理调整。

普通人行门净宽可从 1.1—1.3 米开始；担架主通路门净宽从 1.6 米开始，转运主廊净宽从 2.4 米开始。使用实际担架、推车和双人搬运代理检查直行、转弯和门扇扫掠，最终按检查结果确定。车道以所建车辆的轮廓和余量决定。

建议每组场景至少有以下 Collections，可按需要细分：
- GEO：建筑结构、可见实体、通路与固定掩体。
- PROPS：可移动或可交互道具，门扇、锁杆、车轮、控制面分离。
- STATES：损坏、维修、亮灯等互斥状态，命名能看懂用途。
- LIGHTS：场景灯及状态变化，区分实体灯具与补光。
- CAMERAS：检查与预览摄像机，标明 S 编号、视点和眼高。
- ACTOR_PROXY：角色身份代理、姿态、朝向。
- MARKERS：玩家动线、交接点、观察点和事件位置。
- COLLISION_PROXY：必要的简单碰撞代理，独立显示和导出；不得把它当作已经完成引擎碰撞验证。

使用简单、唯一、便于导出的 ASCII 对象名，如 ENV_D_DOOR_Inner_01、PROP_06_Trolley_01；中文说明写在自定义属性和清单中。保持可编辑的基础模块，复用物体用实例，避免合成一个难以拆分的大网格。

工程内可以使用 View Layers 或独立 Scenes 呈现不同剧情状态。切换状态时，门、车辆、伤员、灯光和坍塌物保持对应。不要用重复复制整张地图制造每个镜头的孤立场景。

## 四、资产完成程度

环境应完成建筑、关键物件、可读材质、灯光和必要的损坏/维修状态。模型的背面、门后、转角和常规玩家视域都需检查；不能只服务单一宣传镜头。

近距离交互道具优先：饭盒/布袋/检修包、维修工具、终端/工卡/无线电、物资箱与名单、通勤车/军用车、转运车与坏轮状态、防护门/锁杆/控制盒、接收控制台/局部升降机、担架/床/布帘/医护包。按 ART_DIRECTION 的 PROP 编号对应，允许模块复用。

人物使用带身份标识的代理体；提供成年人、儿童、持枪人员和医护等必要比例，布置九名具名人物的实际出场位置及年龄/伤情状态。枪械可以使用轮廓代理支持持握与遮挡检查。材质清单必须标明哪些是代理、临时、完成，避免误把灰模列为最终资产。

贴图按近景重要性分配，优先复用材质和贴图集，不统一堆叠高分辨率。能在 Blender 中正确显示的程序材质并不必然可被游戏引擎导入；关键环境表面提供可迁移的基础 PBR 纹理，或明确列出仍需烘焙的项目。透明、发光、监控屏幕和灯光各自记录后续导入要求。

## 五、交付目录建议

output/
- README.md：Blender 版本、打开方式、单位/轴向/原点、总览与分场景关系、状态切换方法。
- blend/MASTER_SCENES.blend：可检查所有场景与连接关系的总览入口。
- blend/environments/：按 ENV-A—F、BG-01—02 分组的可编辑工程；若使用一个总工程即可覆盖，可避免机械地复制八份，说明各组所在 Scene/Collection。
- textures/：外部纹理；若全部已打包进 .blend，在 README 中说明并检验。
- previews/：每组至少一张人眼或剧情视角图、一张俯视或布置图，共至少十六张；另补关键身体接触/门通行截图。
- SCENE_INVENTORY.md：八组场景、十九子空间、S01—S12 对应与真实完成状态。
- ASSET_INVENTORY.md：资产编号、用途、所在文件/Collection、完成/代理状态、外部来源与许可。
- OPEN_ITEMS.md：未完成项、引擎接入事项、已知限制；没有事项也明确写明。
- exports/：可选通用 glTF/GLB；仅在能够导出后重新导入验证时提供，不能用导出文件代替 .blend。

以上输出名称是建议。以可找到、可重新打开、不缺资源为准。不要只回传脚本、渲染图或制作方案。最终提供一个包含必要工程与依赖的可下载交付包，并另列入口文件。

## 六、交付前实际检查

1. 八组场景都有实际几何、材质和光照；十九个子空间在清单与工程里能一一定位。
2. S01—S12 都有场地与摄像机/角色站位对应，关键故事顺序未改变。
3. 成人、儿童、担架与车辆的尺度成立；检查门宽、转角、掩体、穿模和镜头遮挡。
4. S09 有真实接防站位和离开掩体的通路；S10 有三人协作救援及接应空间；S11 有治疗、探视及孟齐仍在治的位置。
5. 关键道具可以单独选择、移动和调整；门轴、车轮、担架与手部接触点有合理位置。
6. 包含所用材质与纹理；在新会话重新打开交付工程，记录实际检查结果。若有外部文件依赖，交付目录使用相对路径。
7. 检查八组预览和俯视图，修复黑画面、无意露空、强烈穿插与主要通路不可读的问题。
8. 如实列出代理人物、待做动画与引擎验证项目。Blender 摄像机走查不代表已完成 FPS 实测，不宣称已经达到一小时或 60fps。

保存工作并回报当前真实产物，不删除中间版本、不清理用户文件。popup=no；delete=no，若实际情况不同须准确说明。
