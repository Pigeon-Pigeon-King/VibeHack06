# 改编概念：固定主线中的共同作战

本概念继承 PRODUCT_BRIEF 与 SOURCE_BIBLE。用户已确定单人、线性、双主角、约一小时 FPS，以及周延牺牲的结局。无需重开类型或结局选择。

## 选定结构
十四章合并为十二段。合并第三、四章的生活与出发准备；合并第九、十章的共同知情、放弃追击与护送行动。其余段落围绕空间和任务重新安排长短。

直接按十四章各做一个短关卡，会使维修、汇报和交接频繁截断战斗。十二段允许宿舍营救、北闸防御、西货廊护送和共同撤回形成连续遭遇，同时给关系变化留出安全、可听清的时段。

体验承诺：玩家先学会靠自己推进战斗，随后必须让其他人完成他们擅长的事，亲眼看到护送、接防和接收继续运转。角色成长落实在撤离顺序、可用通路、同伴站位与任务交接中。

## 玩家能动性
| 层面 | 玩家可以决定或影响 | 固定内容 |
| --- | --- | --- |
| 战斗 | 掩体、移动时机、武器、威胁处理顺序、短距离推进路线 | 任务顺序与故事结果 |
| 交互 | 查看相关信息、靠近人物、操作设备、参与短程搬运；少数安全区观察顺序可变 | 不通过隐藏分数改变关系和生死 |
| 剧情 | 理解角色收到的信息，执行已经作出的承诺，看到操作带来的通路与救援成果 | 闻川放弃追击；周延公开情报、接受交接、最终牺牲 |

分支语法：单一主干，局部战术路径在同一目标处汇合。没有对话树、关系值、追击结局或“完美操作救活周延”路线。signature_command：N/A；使用明确的情境交互。

## 核心循环
观察同伴及前方压力 → 通过射击和移动建立通行条件 → 完成短而具体的交互 → 看到人或物真正通过 → 获得下一步目标。
任务完成由相应局面成立触发，采用有限敌群和已交代的增援入口。角色等待玩家时有合理停留位置；关键NPC也会完成自己的工作。

玩法先例沿用用户所说的使命召唤式线性战役语法：第一人称推进、队友提示、双视点切换、短剧情演出与战斗相接。角色、地图、台词和资产按本作原创设计。

## 两个需要验证的问题
1. 闻川的固定取舍是否被理解为人物决定？用监控和通信说明现实机会及护送代价，不显示可选的“追击邵原”任务，再让玩家亲手完成护送。
2. 周延受伤时的控制权交接是否会被误读为失败？先完成可玩救援目标，明确进入协作动作演出，再发生固定伤情；孟齐获救与交接成果继续保留。

最大操作风险是共同救援中的夺控、第一人称身体动画与固定伤亡衔接。后续优先以真实3D白盒验证这段；文本方案只证明意图与因果可说明。

## 内容预算与判断
六组主要空间，九名具名人物，三种基础枪械外观，有限敌群，十三分钟专门演出。成长反馈优先制作在孟齐接防、罗敬留岗、周延接受保护与闻川完成接应上。

若试玩者持续认为自己被强迫错过一个可选任务，修订S08的目标提示及监控呈现。若试玩者反复读档试图消除周延的剧情伤情，修订S10的操作结束、演出开始和检查点位置。两种结果都需要实际观察，目前未验证。
