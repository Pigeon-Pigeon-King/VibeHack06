# FB-014 · 起跳后接地误判截断竖直速度

日期：2026-10-31。用户反馈跳跃似受限制，感觉滞空长但高度不高。状态：已确认并修复实际 Rapier 路径中的起跳接地误判，专项回归通过；修复位于以 `4a74263` 为基线的反馈候选，后续由主窗口整合。没有修改重力或起跳速度，没有浏览器／真人／Windows 验收结论。

## 参数与物理边界

基线 `4a74263` 的 `src/runtime/Physics.ts` 使用重力 `g=1.428 m/s²`、固定步长 `1/60 s`，接地起跳时把竖直速度设为 `v₀=1.65 m/s`。角色是运动学胶囊，竖直速度由项目代码积分；Rapier 负责实际位移裁剪和接触检测，不是给动态人体刚体施加了一次力学冲量。

反馈窗口核对的 [JPL 卫星物理参数](https://ssd.jpl.nasa.gov/sats/phys_par/) 给出木卫三 `GM=9887.83275 km³/s²`、平均半径 `2631.20 km`。由 `g=GM/R²` 换算得到 `1.428214 m/s²`，与运行值相差约 0.015%。当前 `v₀=1.65 m/s` 是既有设计输入；[交接玩法分册](../handoff/current/05_GAMEPLAY_AND_PRESENTATION.md) 明确称其为调试起点。

忽略顶棚、空气阻力和落点高差，用这两个参数得到：

- 最高上升量 `h=v₀²/(2g)=0.953256 m`。
- 上升时间 `t↑=v₀/g=1.155462 s`。
- 回到相同高度的时间 `T=2v₀/g=2.310924 s`。

这说明当前参数在数学上自洽，不能说明它是唯一的“正常人体最大跳高”。人体的起跳能力还取决于起跳冲量／做功、质量、动作和装备；仅凭重力无法推出唯一的 `v₀` 或跳高。本轮保留既有 `g` 和 `v₀`，只处理阻断既定轨迹的接地逻辑。

## 已确认的限制来源

`Physics.move()` 起跳时先写入 `1.65`，再扣除一帧重力，因此第一帧速度是 `1.6262 m/s`、向上请求位移约 `0.0271033 m`。实际 Rapier 控制器在这一帧仍可返回 `computedGrounded() === true`。键盘和触屏跳跃都是一次输入边沿，下一帧 `jump` 已为 `false`；原逻辑 `if (body.grounded && !jump) body.verticalSpeed = -0.2` 随即覆盖仍应为正的上升速度，随后吸附回地面。

在没有顶棚的夹具和北闸真实出生点 `[-8,0,40]` 都复现了同一结果：只上升 **0.0271033 m（2.71 cm）**。这不是顶棚裁剪，也不是重力值过大。低顶棚真正裁剪发生在 `delta.y < desired.y - 0.001` 且仍上行时，届时竖直速度清零；该行为应继续保留。

内存对照仅把接地赋值改为：

```ts
body.grounded = this.controller.computedGrounded() && body.verticalSpeed <= 0;
```

对照不修改 `g`、`v₀`、胶囊、顶棚或地面，恢复了预期自由上升；中途再次按跳不会获得第二次冲量。反馈窗口已向主窗口说明共享文件的最小改动，在独立反馈树把这一行和解释注释放入 `src/runtime/Physics.ts`，新增测试直接运行该真实源文件。

其它既有条件：只有接地才能起跳；`staged` 演出、`cooperative` 搬运及 S10 指定受限阶段不接受起跳。普通战斗和工作模式的跳跃没有独立最大高度钳制。成人站姿高 `1.8 m`、蹲姿高 `1.2 m`、胶囊半径 `0.28 m`；控制器间隔 `0.015 m`、自动台阶高 `0.28 m`、吸附距离 `0.25 m`。抬头空间不足会限制上升，蹲伏起身还会做独立净空查询。
