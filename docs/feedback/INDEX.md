## 处理与状态

1. 对照真实代码及实际运行版本复现，分类为 **bug／体验调整／新功能**；资产要求另标为 **资产验收约束**。先说明已确认的影响模块、文件和关联章节，未确认的标为待查。
2. 记录原因、最小修复方案、并行依赖与必要回归。范围清楚的可逆修复直接推进；涉及剧情、玩法方向、已审定美术或不兼容取舍时才提出必要问题。
3. 用原复现步骤检查修复，并覆盖真正受影响的关联行为。证据标明版本、环境、操作、结果和未测项；静态读码、自动测试、工具操作、真人试玩分别记录，占位表现不称为正式资产。
4. 有实际修复及对应证据后才能关闭问题。同步更新本索引、[开发进度](../../artifacts/game-progress.md) 与任务纵览台中真正受影响的节点；Nativue 按 [本地约定](../NATIVUE.md) 更新。纯建档不改变功能完成度或验证状态。

状态使用：`待排查 → 已复现／已确认需求 → 修复中 → 待验收 → 已关闭`。`待补信息`、`待并行工作合入`、`待模型产出`须写明依赖；`暂未复现`保留现场条件，不等于已关闭。关闭后复发可重新打开。

### FB-001 · 成人基础骨架与儿童适配

| 修复／检查方案 | 模型产出后记录资产 ID、版本和文件，核对骨骼层级及成人共享情况；检查蒙皮权重、关节弯折、脚底与手部接触；儿童单独验证比例、步幅和动作。按角色用途在 Three.js 中验证移动、持枪／装填、受击／倒地，以及抱撤、护具调整、搬运、担架或医疗等所需动作；发现缺陷后逐项修整并复查 |
