# FB-003 · 队友站桩与双方掩体行为

日期：2026-10-31。分类：战斗体验问题＋缺失的战术行为。状态：已确认代码原因；未实现修复，未关闭。

## 现象与复现范围

用户反馈“队友人物好像基本都在挂机，双方也都不太会找掩体”，进一步说明“大部分都是，纯站桩输出”。不限定单章；反馈所对应的具体运行包未确认。本文对 `main@4fd68c5` 的 0.6.0 代码核查，尚无本窗口完整战斗操作复现。

预期：战斗中的移动、观察、开火、利用掩体和换位能被看见，队友能实际支援；不抢走剧情站位、伤员搬运、接防到岗和撤离任务。

## 已查明的原因与影响

- `src/mission/Simulation.ts` 的 `updateActors()`：敌人进入可见射界并处于最近两名攻击者时，将 `speed` 直接设为 0；不会先确认自己已经到达有效掩体。这会提前打断仍有 goals 的推进。
- 同伴射击只对部分章节／角色开放，并要求 `!a.goals.length`。到达预设位置后能够真实发射弹丸，但不存在通用的自主战斗换位；射击能力不能证明战术行为完成。
- `src/actors/Navigation.ts` 是通行路径搜索，没有掩体候选、威胁方向、遮挡／射界评分、占位或探身退回机制。既有章节 posts 与掩体几何并不自动成为动态战术系统。
- S09 接防支援、S10 Q 请求掩护已有专用动作和命中证据，应保留；不能把反馈概括为“所有 NPC 完全不会开火”。

实际影响为共享 NPC 战斗更新、导航与场地掩体、角色姿态表现，以及所有相关章节的任务条件。代码修改将触及 `Simulation.ts`，不是方向 HUD 模块的一部分。主窗口本轮原先正在改相同文件，后已合回 main；下一次实施前仍需重新检查两个 checkout。

## 修复方案与验收要求

1. 先将任务指令与战术移动分开：护送、接防、搬运、撤离和剧情锚点优先，不能靠战术 goals 替换任务 goals。
2. 依据当前威胁和真实碰撞选择可达、具有遮挡且有射击出口的近处掩体；防止双方挤到同一位置，控制搜索频率和移动范围。
3. 敌人推进到合适站位后短点射、观察、换位；失去视线只使用最后已知位置，不隔墙追踪。队友在允许支援的阶段有实际压制与协同移动，不以无意义往返摆动冒充智能。
4. 保存／恢复战术状态的处理须明示；回归原先章节的到岗判定、伤员接触、Q 掩护、暂停／重试和任务终态。

待补证据：至少普通交火、守点、护送／撤回三类场景的正常速度连续录像；移动轨迹、射击与命中、真实遮挡、探身和归位；检查点恢复；CPU／路径搜索成本。静态读码只支持上述原因判断，本轮没有把 AI 改进标为完成。
